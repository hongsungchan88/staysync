## 2. 시연 대본 × 배포 환경

시연-01 2절의 여덟 장면을 `https://staysync.kr`(심사자 계정, 27차 브라우저 확인)에 맞춰
봤다. **확인-08 의 리허설은 로컬 시연 시드로 한 것이고, 배포 환경에는 시드를 올리지
않기로 했다.** 그래서 "리허설이 끝났으니 잡히면 그대로 쓴다"는 인계메모의 판단은
배포 환경에서 성립하지 않는다.

| | 장면 | 배포 환경에서 | 이유 |
|---|---|---|---|
| 1 | 통합 캘린더 | **된다** | 판매 단위 셋이라 "30객실 90일 0.4초"는 화면을 보며 말하지 않는다(확인-08 6절) |
| 2 | **Mock 채널 예약 → 다른 채널 재고 자동 감소** | **안 된다** | 시뮬레이터를 배포하지 않았다(작업지시-15 5절 5번). 판매 단위마다 채널이 에어비앤비 iCal 하나뿐이고, iCal 은 재고를 받지 않는다 |
| 3 | **동시 판매 → 충돌** | **안 된다** | 충돌 0건. 채널이 하나라 충돌이 생길 경로가 없고, 위젯은 막힌 날짜를 팔지 않는다 |
| 4 | 요금 일괄 편집 | 된다, **주의** | 업체의 실제 요금 데이터다. iCal 로 밖에 나가지는 않지만 위젯 금액이 바뀐다. 시연 뒤 되돌려야 한다 |

## 4. 교수에게 적은 문장 중 확인 안 된 것

**중간 점검 보고서 6절 2번**이 "Channex 스테이징의 부킹닷컴 공용 테스트 숙소"로 예약
수신을 검증하겠다고 적었다.

- **Channex 문서로는 있다(09-17 확인).** 통화별 테스트 숙소가 여섯 개 이상이고, 방과
  요금제를 둘 다 매핑해야 채널이 켜지며, 부킹닷컴 테스트 예약 주소와 테스트 카드로 예약을
  만들 수 있다. 익스트라넷은 없고 API 로만 다룬다. 한 숙소(10745030)는 예약이 안 된다고
  적혀 있다
- **우리 스테이징 계정의 채널 목록에도 있다(09-17, 사용자 로그인 뒤 Cowork 확인).**
  Channels → Create 의 채널 목록(57개)에 Booking.com 이 있다. **정정할 필요 없다. 닫는다**

### 계정 상태 (09-17)

| | 상태 |
|---|---|

| 채널 목록 | 57개. Booking.com·Airbnb·Agoda·Expedia·Trip.com 있음. **국내 채널 없음**(조사-04 와 같다) |
