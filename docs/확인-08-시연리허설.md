# 확인 08. 업체 회의 시연 리허설

- 확인일: 2026-09-11
- 범위: `시연-01-업체회의-시나리오.md` 2절의 12분 대본
- 방법: Cowork 세션이 내장 브라우저로 직접 조작. 시드는 Claude Code
- 관련: 시연-01, 확인-05·06, CLAUDE.md

**업체 회의는 구두 설명으로 끝나 시연을 하지 않았다.** 리허설에서 나온 것은 그대로
유효하다 — P6 23주차 리허설과 10월 배포 뒤의 확인에서 다시 쓴다.

**브라우저 확인이 또 결함을 잡았다.** 7·9·10·14·15주차에 이어 여섯 번째다.
자동 테스트 432건이 전부 통과하는 상태였다.

---

## 1. 무엇을 했나

화면 여덟을 브라우저로 직접 열고 눌렀다 — 로그인, 캘린더, 충돌, 인박스, 청소 칸반,
리포트, 위젯, 그리고 시뮬레이터(8081). 세 차례 돌았고 사이사이 Claude Code 가 고쳤다.

## 2. 리허설이 잡은 것

### 1차 — 화면 셋이 비어서 열렸다

| 무엇 | 왜 |
|---|---|
| 캘린더 기본 화면에 예약 0건 | 시드가 전부 지난 60일이라 오늘부터 그려지는 창이 텅 비었다 |
| `/conflicts` 0건 | 충돌을 만든 적이 없었다 |
| `/inbox` 0건 | 메시지를 넣은 적이 없었다 |
| 리포트 채널 믹스에 `DIRECT`/`MOCK_OTA`/`AIRBNB` | 캘린더 범례는 한글인데 리포트만 코드를 그대로 노출 |
| 위젯에 숙소 이름 없음 | 공개 페이지인데 어느 숙소인지 안 보인다 |

**셋 다 데이터가 없어서지 코드가 틀려서가 아니었다.** 그러나 시연은 화면이 비면
끝이다. **"자동 테스트가 통과한다"와 "보여 줄 수 있다"가 다른 자리다.**

### 시드 스크립트가 잡은 것 둘

Claude Code 가 시드 뒤에 리포트를 직접 조회하는 검증을 붙여 두어 걸렸다.

- **취소율 0.** 취소를 가장 오래된 예약에서 골라 6월 건이 걸렸는데, 취소율은 숙박
  기준이라 체크인이 리포트 기간 안에 있어야 잡힌다
- **요금이 판매 단위별로 안 갈렸다.** 숙소 단위로 묶어 넣어 다락방이 본채와 같은
  18만원에 팔리고 있었다. **캘린더를 열어 보고 발견했다**

### 2차 — 셋

- **인박스 게스트 이름이 4건 다 `Booking.com Guest`, 채널도 4건 다 부킹닷컴.**
  대본 5번이 "채널별로 흩어진 메시지를 한 화면에"인데 한 채널에 영문 더미였다
- **충돌 4건이 같은 사건의 중복.** 3절 2번을 볼 것
- **체크아웃할 `CHECKED_IN` 예약이 있는지 화면에서 확인 불가.** 3절 4번

### 덤으로 나온 진짜 결함 하나

**캘린더 예약 막대가 전부 회색으로 그려지고 있었다.** 채널 코드가 `MOCK_OTA`·`AIRBNB`
라 프론트의 라벨·색 맵에 없었고, 맵에 없으면 조용히 기본색으로 떨어진다.
**리포트의 코드 노출을 고치러 갔다가 같은 원인이 캘린더에도 있던 것이 드러났다.**

예외도 경고도 없다. 캘린더는 멀쩡히 그려지고 막대도 보인다. 색만 정보를 잃는다.
**정상 경로에 증상이 없는 결함의 전형이다.**

## 3. 고치지 않고 남긴 것 넷

### 1. 채널로 수신된 예약이 `reservation_night` 행을 만들지 않는다

가장 무겁다. `ReservationWriter` 는 `writeNights` 를 부르는데 `ChannelBookingWriter`
는 부르지 않는다. 리포트의 판매 객실박·매출·채널 믹스가 전부 그 테이블을 읽으므로
**실제 채널 예약이 리포트에서 빠진다.**

**재고 원장은 정상이라 캘린더는 맞게 보이고 리포트만 조용히 적게 센다.**

- **완료 조건 13·14 가 이것을 못 잡았다.** 13은 산식, 14는 기간·숙소 필터만 본다.
  **채널로 들어온 예약이 리포트에 반영되는지를 보는 테스트가 없었다.** 두 경로가
  밤을 쓰는 방식이 다른데 한쪽만 덮었다
- **고칠 때 그 테스트를 함께 박는다**
- **P4 완료 보고서를 보내기 전에 고친다.** 보고서 3절이 채널 믹스를 만든 것으로
  적고 있는데, 채널 예약이 안 세어지면 그 문장이 사실이 아니다

### 2. 같은 (날짜, 판매 단위) 충돌이 여러 행으로 쌓인다

`ChannelBookingWriter.raiseConflicts` 가 기존 OPEN 충돌을 찾지 않고 (예약, 날짜)마다
무조건 save 한다. 초과 예약 2건이 각각 행을 만들어 같은 날짜가 두 카드로 뜬다.

**의도로 보이지 않는다.** 스키마의 `reservation_ids BIGINT[]` 는 날짜당 한 행에
관련 예약을 모으려던 모양이고 `(unit, stay_date)` 유일 제약도 없다. 결과적으로
**먼저 생긴 카드가 더 적은 예약을 담은 낡은 스냅샷으로 남고, 하나를 해소해도 다른
하나는 열려 있다.**

### 3. `GET /api/reservations` 에 `from`/`to` 를 주면 500

`(:from is null or ...)` 의 형 추론 실패다. 화면이 부르지 않는 경로라 증상이 없다.

### 4. 화면이 없는 쓰기 경로 셋 — 배포에 직결된다

| 무엇 | 상태 |
|---|---|
| 회원가입 | **화면 없음.** API 만 있다. `LoginPage.tsx` 주석이 "7주차에는 개발용 계정 하나면 된다"고 적어 둔 의도적 결정이다 |
| 숙소·판매 단위·요금제 등록·편집 | **화면 없음.** API 만 있다 |
| 예약 체크인·체크아웃 | **화면 없음.** 화면에서 예약에 하는 쓰기는 막대를 끌어 날짜를 바꾸는 PATCH 하나뿐이다 |

**지금까지는 문제가 아니었다.** 개발용 계정 하나로 돌렸고 데이터는 API 로 넣었다.
**남이 접속해 써 보는 순간 셋 다 막힌다.** 10월 말 배포 목표의 범위 산정에
이것부터 들어가야 한다.

리허설에서는 체크아웃을 `python tools/demo_checkout.py 73` 으로 걸었다.

## 4. 화면에서 정상으로 확인된 것

- **요금이 판매 단위별로 갈리고 주말 +30% 가 캘린더와 위젯에서 일치한다.**
  본채 180,000 + 234,000 = 위젯 2박 414,000
- **리포트 지표 여섯과 채널 믹스 네 채널이 다 뜬다.** 점유율 24.0 / ADR 185,114 /
  RevPAR 44,508 / 리드타임 21.3일 / 취소율 5.3%
- **`RevPAR = ADR × 점유율` 이 실제 값으로 성립한다.** 화면의 반올림된 점유율로
  곱하면 수십 원 어긋나는데 표시 자리 때문이고 계산은 맞다
- **위젯이 로그인 없이 열리고, 다녀와도 호스트 세션이 끊기지 않는다.**
  CLAUDE.md 가 적어 둔 `apiRequest` 트랩이 실제로 막혀 있다
- **충돌 화면에 해소 방법 넷과 "옮길 판매 단위" 선택이 나온다**
- 콘솔 에러는 첫 로드의 401 하나뿐이고 로그인 전 세션 복구 시도라 정상이다

**위젯의 숙소 이름은 날짜를 넣은 뒤에 뜬다.** 가용 조회 응답에 실려 오는 구조다.
빈 화면에는 "예약하기"만 있다. 결함은 아니나 공개 페이지의 첫인상이므로 적어 둔다.

## 5. 판정

**시연 대본 여덟 단계가 전부 화면에서 돈다.** 2번(Mock 채널 예약 수신)만 브라우저로
확인하지 못했다 — 시뮬레이터에 화면이 없고 REST 뿐이라 명령으로 쏴야 한다.

```
curl -X POST http://localhost:8081/api/scenarios/duplicate \
  -H 'Content-Type: application/json' -H 'X-Api-Key: mock-ota-dev-key' \
  -d '{"booking_id":"LIVE-1","room_id":"mock-room-1", ...}'
```

**함정 둘.** `X-Api-Key` 가 시나리오 경로에도 필요하다. 그리고 Git Bash 의 curl 은
본문의 한글을 cp949 로 망가뜨려 400 이 난다 — 한글이 필요하면 UTF-8 파일로 저장해
`--data-binary @파일` 로 보낸다. 파이썬으로 쏘면 이 문제가 없다.

## 6. 시연 자체에 남는 조언

- **리포트는 기간을 지난 60일로 맞춰 놓고 시작한다.** 기본값이 이번 달이라 절반이
  미래이고 점유율이 낮게 보인다
- **리포트 기간을 그 창 밖으로 넓히지 않는다.** 3절 1번 때문에 채널 수신 예약이
  캘린더에는 있고 리포트에는 없는 상태가 두 화면에 동시에 뜬다
- **충돌 목록을 스크롤하지 않는다.** 첫 카드만 연다. 3절 2번 때문에 같은 예약번호가
  반복돼 보인다
- **위젯은 열자마자 날짜부터 넣는다.** 빈 화면에 숙소 이름이 없다
- **"30객실 90일 0.4초"를 화면 보면서 말하지 않는다.** 판매 단위가 3개뿐이라 화면과
  말이 안 맞는다. 측정은 실제로 했으므로 따로 떼어 인용한다
- **시연용 시드 데이터를 배포 환경에 올리지 않는다.** 가짜 게스트 이름이 남의 눈에
  띈다. `tools/seed_demo.py` 는 로컬 전용이다
