## 1. 왜 필요한가

10-20 저녁 교수님·업체가 있는 단톡방에 `https://staysync.kr` 링크를 보냈다. 휴대폰으로 열 가능성이 크다.
Cowork 이 배포 환경을 375px(휴대폰)·800px 폭으로 열어 봤다(10-20).

- **375px — 캘린더를 쓸 수 없다.** 표가 왼쪽에 60px 남짓으로 눌리고, 오른쪽 "기간 선택" 패널이 화면 대부분을 차지해 날짜가 하나도 안 보인다.
  제목과 메뉴 글자가 한 글자씩 세로로 쪼개진다("통/합/캘/린/더", "숙/소")
- **800px — 메뉴 글자가 단어 중간에서 끊긴다**("숙/소", "채널 연/결", "비밀번호 변/경"). 지금 어느 화면인지 표시가 없다.
  비밀번호 변경·로그아웃이 주 메뉴와 같은 모양으로 섞여 있다
- 리포트·청소·인박스는 375px 에서도 읽힌다 — 이번 범위 밖

## 2. 이번에 만드는 것

### A. 좁은 화면의 캘린더

- 좁은 화면(휴대폰 폭)에서 캘린더 표가 **화면 전체 폭**을 쓴다. 판매 단위 이름 칸은 좁게, 날짜 칸은 가로로 넘겨 본다(지금 넘기기 그대로)
- 오른쪽 패널(기간 선택·요금 편집·예약 내용·예약 추가)은 좁은 화면에서 **표 아래나 화면 아래에서 올라오는 판**으로 바뀐다.
  아무것도 고르지 않았을 때는 "예약 추가" 버튼만 작게 보이고 설명문은 숨는다. 칸을 고르거나 막대를 누르면 열리고, 닫기로 접힌다
- 넓은 화면(지금 데스크톱)의 배치는 바꾸지 않는다
- 좁은 화면에서 칸 끌어 선택이 터치로 어려우면 그대로 둔다(이번 범위 밖) — 대신 시작·끝 날짜를 패널에서 직접 넣는 길(작업지시-23)이 있으니 막히지는 않는다. 8.1 에 터치로 해 본 결과를 한 줄

### B. 상단 메뉴

- 제목("통합 캘린더")과 메뉴 글자가 **단어 중간에서 줄바꿈되지 않는다**
- **지금 화면**의 메뉴가 구분돼 보인다(색·밑줄 등 담백하게)
- 비밀번호 변경·로그아웃은 주 메뉴와 떨어진 오른쪽 끝(계정 자리)으로. 모양도 주 메뉴와 구분
- 좁은 화면에서는 메뉴가 한 줄 가로 넘기기거나 접는 메뉴(햄버거) 중 하나 — 새 의존성 없이, 키보드로도 열린다
- 숙소 고르기(숙소가 둘 이상일 때)와 선택된 숙소 이름이 좁은 화면에서도 한 줄로 읽힌다
- 같은 머리말을 쓰는 다른 화면(숙소·채널 연결·충돌·인박스·청소·리포트·비밀번호)에도 같이 적용된다 — 머리말이 화면마다 따로면 한 곳으로 모으지 말고 각각 맞춘다(구조 변경 최소)

- 기능·문구 변경(배치에 필요한 짧은 버튼 이름은 예외 — 바꾸면 8.1 에 적는다)

## 4. 지켜야 할 제약

- 기능·API·데이터 변경 없음. 마이그레이션 없음
- 새 의존성 없음. 기존 CSS 방식(파일·변수)을 그대로 따른다
- 넓은 화면(1280px 이상)은 지금과 같아 보여야 한다 — 바뀌는 것은 메뉴의 현재 화면 표시·계정 자리·줄바꿈뿐
- 접근성 — 메뉴는 링크 그대로(현재 화면 `aria-current`), 접는 메뉴는 버튼에 `aria-expanded`, 아래 판은 닫기 버튼과 Esc

## 8. 진행 상황

### 8.1 구현과 테스트

브랜치 `ui/narrow-calendar-nav`(10-20). **프론트 배치만 — 기능·API·데이터·마이그레이션 변경 없음, 새 의존성 없음.** 좁은 화면 경계는 Tailwind `md`(768px) 하나다.

**A — 좁은 화면의 캘린더.**
- 표가 화면 전체 폭 — 좁으면 본문·패널이 세로로 쌓이고(`max-md:flex-col`) 본문 여백 `p-1`
- 판매 단위 칸 216px → **96px**(`layout.ts` `NARROW_LEFT_W`). 가상 스크롤·막대 위치·포인터 좌표가 같은 값을 써야 해서 CSS 가 아니라 `useNarrow()`(새 훅, `matchMedia('(max-width: 767px)')`) 로
  골라 `CalendarGrid` → `useRangeSelection` → `cellAt`(인자 기본값은 그대로 216 — 기존 테스트 불변)·`UnitRow`·`Bar` 로 넘긴다. 좁으면 모서리 칸 글자 "판매 단위 N개" → "N개"
- **그리드의 `touch-none` 을 좁은 화면에서 뺐다.** 전에는 휴대폰에서 손가락으로 표를 넘길 수 없었다(터치가 전부 칸 선택으로 갔다) — "날짜 칸은 가로로 넘겨 본다"의 전제라 같이 고쳤다.
  대신 좁은 화면에서는 끌어 범위 선택이 안 되고, 누르면 한 칸이 골라진다(기간은 패널의 시작·끝 날짜로 고친다, 작업지시-23). 넓은 화면은 그대로 `touch-none`
- 오른쪽 패널 → **표 아래 판**(`panel-dock`, 최대 55vh, 넘치면 판 안에서 스크롤). 아무것도 안 골랐으면 "예약 추가" 버튼만(설명은 `max-md:hidden`). 칸을 누르면 요금·제약 편집, 막대를
  누르면 예약 내용, "예약 추가"는 입력 판이 열린다. 닫기 — 요금·제약 편집에는 판 위에 **"닫기"**(좁은 화면만), 예약 패널·예약 추가는 원래 닫기 그대로. **Esc** — 좁은 화면에서 칸 선택·예약 패널을
  닫는다(넓은 화면 동작은 바꾸지 않음), 예약 추가 판은 폭과 상관없이 Esc 로 닫는다(오늘 들어온 패널이라 넓은 화면에도 단다)
- 같이 보인 것 — 판을 닫아도 표의 회색 선택 표시는 남는다. 표 안쪽 상태라 넓은 화면에서 막대를 눌렀을 때와 같은 기존 동작이다(고치지 않았다)

**B — 상단 메뉴(`CalendarPage` 머리말).**
- **줄바꿈** — `index.css` 의 `body` 에 `word-break: keep-all` 한 줄. 한국어가 글자 단위가 아니라 띄어쓰기에서만 줄바꿈되어 모든 화면에서 "숙/소"·"채널 연/결" 이 사라진다.
  제목·메뉴·계정에는 `whitespace-nowrap` 도 걸었다
- **지금 화면** — 메뉴를 `NavLink` 로 바꾸고 맨 앞에 "캘린더"(`/`)를 더했다. 지금 화면은 `aria-current="page"`·테두리와 글자가 강조색(`clay`)·굵게. 다른 항목은 지금과 같은 테두리 버튼 모양
- **계정 자리** — 비밀번호 변경·로그아웃을 메뉴 묶음 오른쪽 끝, 세로 구분선 뒤 `role="group" aria-label="계정"` 으로 떼고 테두리 없는 흐린 글자로
- **좁은 화면** — 머리말이 줄바꿈으로 둘로 나뉘고(제목·숙소 / 메뉴·계정), 메뉴는 **한 줄 가로 넘기기**(`overflow-x-auto`, 링크라 Tab 으로 차례로 닿는다). 햄버거는 만들지 않았다. 숙소 고르기는
  `max-w-[14rem] truncate`, 숙소 이름(하나일 때)은 `truncate whitespace-nowrap` 으로 한 줄
- **다른 화면**(숙소·채널 연결·충돌·인박스·청소·리포트·비밀번호)은 각자 머리말(제목 + "캘린더로")이라 모으지 않았다 — 줄바꿈은 위 `keep-all` 로 같이 고쳐진다. 그 화면들에는 주 메뉴가 없어
  "지금 화면" 표시는 제목이 맡는다(구조 변경 최소)
- 문구 변경 — 메뉴에 "캘린더" 한 항목 추가, 좁은 화면 모서리 칸 "N개"뿐

**테스트.**
- 프론트 `calendar/CalendarPage.test.tsx`(새, 3건) — 메뉴: "캘린더"만 `aria-current="page"`, 나머지 여섯 없음, 로그아웃은 주 메뉴 밖, 계정 묶음에 비밀번호 변경(`/account/password`)·로그아웃 /

- **전체(10-20, 차례로)** — 백엔드 **414** + 시뮬레이터 **37**(바뀌지 않음, 실패 0) → 프론트 **153**(150 + 3, 23 파일) · `npm run build` 통과
