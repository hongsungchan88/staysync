## 2. 확정된 사실 — 21 의 9절과 다른 곳

1. **채널 설정 이름이 문서와 다르다.** 콘솔의 Booking Total Type 선택지는 `Payout Amount`·`Amount including Commission` 둘뿐이다.
   21 9절·확인-12 6.2 의 "Total Paid Amount" 대신 **`Amount including Commission`** 으로 만들었다(취지 — 게스트 결제액 = 리스팅 가격, 호스트 전용
   수수료 15.4%). Min Stay Type `Arrival`, 알림 메일 끔. 21 9절 3번과 확인-12 6.2 의 그 이름을 고친다(4절 A)
2. **호스트 계정에 리스팅이 8개다.** 고양 숙소 여러 개, 서울 메종드서촌 여러 개, **고양에 이름이 같은 "지니하우스"가 하나 더 있다.**
   **대상은 서울 홍대 지니하우스 — 리스팅 id `1450311972082292442`.** 고양 "지니하우스/호수공원…"(`1050365893618564330`)은 다른 숙소다.
   다른 리스팅은 매핑하지 않는다. 잘못 매핑하면 그 숙소 요금·달력이 우리 값으로 덮인다
3. **요금 기준값(호스트 답, 10-04·07)** — 평일 170,000 · 금·토 221,000 · 최소 숙박 1. StaySync 는 10-06 에 이미 맞췄다(2026-10-04~2027-10-03,
   금·토 104일 221,000, 나머지 261일 170,000, 최소 숙박 전부 1). 할인 넷 — 주간 7박+ 3%, 월간 28박+ 5%, **막바지 10% = 체크인 당일~1일 전**,
   **조기예약 5% = 체크인 3개월 전**. 날짜 지정 맞춤 프로모션은 연결 동안 못 만들 수 있다고 호스트에게 알렸다
4. **연결 링크는 짧게만 유효하다**(10-14 실측 — 몇 시간 뒤 `invalid_state`). 다시 승인이 필요해지면 "호스트 대기 → 만들자마자 전달 → 즉시 승인"
5. 승인 직후 호스트 화면에 "Connection is unsuccessful"이 떴지만 Channex 쪽은 성공했다(Host ID 채워짐, 채널 생성). 같은 화면이 다시 떠도 콘솔로 판단한다

### B. 해제(10-21) 뒤 iCal 로 돌아갈 때 — 중복이 생기는가 (가장 중요)

그때 **Channex 가 넘겨받은 예약(채널 코드 `AIRBNB`, Channex 외부 id)과 iCal 이벤트가 같은 예약으로 이어지는지, 새 예약 + 충돌이 되는지**를
코드로 보고 **로컬에서 실제로 돌려 본다**(확인-12 2절 리허설에 해제 단계를 붙인다). 연결 기간에 Channex 로 새로 들어온 예약도 같은 질문이다.

- 중복이 생기면 **해제 절차를 정해 8.1 에 적는다** — 예: iCal 쪽이 같은 판매 단위·같은 체크인·체크아웃의 Channex 예약을 넘겨받는 반대 방향,
  또는 해제 뒤 iCal 을 다시 켜지 않고 Channex 예약을 그대로 두는 길. **코드를 바꿔야 하면 멈추고 보고한다** — 사용자가 정한다

3. 매핑 대상은 리스팅 하나(`1450311972082292442`)뿐
4. 해제는 **매핑 해제 + 채널 비활성화**까지. 채널 삭제는 하지 않는다(삭제하면 에어비앤비 쪽 연결도 끊겨 다시 쓰려면 재승인이 필요하다 — 심사 뒤 업체와 정한다)

   후보가 정확히 하나일 때만, 금액·게스트·인원은 유지, 감사 `CHANNEL_TAKEBACK`. 둘 이상이거나 날짜가 다르면 새 예약 + 충돌(8.1)
