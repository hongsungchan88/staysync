# 조사 04. 에어비앤비 중개 연동 — 어느 서비스를 거칠 것인가

- 조사일: 2026-09-17
- 계기: 교수 방향(사용자 전달, 09-17). AI 보다 CMS·PMS 가 제대로 도는 것이 목적이고,
  업체가 써 보고 판매 가능성이 보이면 판매도 시도한다. 차별점 하나가 **에어비앤비 공식
  API 대신 중개 서비스를 거친 양방향 연동**이다. 교수가 말한 "우회 사이트"가 어느 곳인지는
  사용자가 확인 중이다
- 대상 사용자: 본업이 있고 숙소 한두 개를 부업으로 내놓는 호스트
- **결정(09-17): 교수가 말한 "우회 사이트"는 Channex 였다.** 이 문서의 1순위와 같다
- **정정(09-17): "13주차에 어댑터를 이미 붙였다"는 사실이 아니다.** `AdapterType.CHANNEX` 선언과
  능력 목록만 있고 구현은 없다(검토-01 3절 7번, 7절). 조사-03 4절의 서술을 그대로 옮긴 것이다.
  아래 본문의 해당 문장은 고쳤다
- 관련: 조사-01(Channex), 조사-02(에어비앤비 iCal), 조사-03(Guesty), 확인-09

---

## 1. 결론

**에어비앤비 공식 API 는 지금도 직접 받을 수 없다.** 공개 API 가 없고 신규 신청을 받지
않는다는 글이 2026년 5월에 갱신됐고, 에어비앤비 소프트웨어 파트너 페이지에도 신청 절차가
없다. 중개 서비스를 거친다는 전제는 맞다.

**조사-03 이 "막혔다"고 본 이유는 풀렸다.** 그때 막힌 것은 API 가 아니라 게시된 리스팅이
없다는 점이었다. 지금은 업체의 게시 리스팅 셋이 있다(확인-09 7절). **중개 연동을 실제
리스팅에서 시험할 수 있는 첫 시점이다.** 대신 영업 중인 리스팅에 재고와 요금을 써 넣는
일이라 업체의 명시적 허락이 먼저다.

**부업 호스트가 대상이면 1순위는 Channex 다.**

- PMS 개발사가 쓰라고 만든 연동 API 다. 호스트는 StaySync 하나만 쓴다
- 에어비앤비 소프트웨어 파트너 페이지에 Preferred+ 로 올라 있다
- 스테이징이 무료이고 가입 즉시 쓴다. **어댑터는 새로 지어야 한다** — 인터페이스·능력 선언·동기화 워커·아웃박스·금액 통로는 있다
- 과금이 휴가용 임대 유닛당 $0.50 라 한두 채 호스트에 맞는다. 월 $130 고정비는 StaySync 몫이다

**약점은 국내 채널이다.** Channex 채널 코드 목록에 야놀자·여기어때·네이버·인터파크·
마이리얼트립·위홈이 없다. 국내 채널이 필요해지면 **ONDA(온다)** 가 보완 후보다. 국내
채널과 에어비앤비를 함께 다루지만 계약을 해야 자격증명이 나오고 단가는 견적이다.

**Guesty 는 부업 호스트에게 이중 구독이 된다.** 호스트 계정 기반의 완제품 PMS 이고,
1–3 리스팅용 Lite 요금제가 우리 대상 고객에게 직접 팔리는 경쟁 제품이다. 교수가 말한
곳이 Guesty 라면 이 점을 정리해 드린다(조사-03 6절에 이어).

## 2. 중개 서비스는 두 부류다

| 부류 | 구조 | 호스트가 쓰는 것 | 예 |
|---|---|---|---|
| **연동 API** | StaySync 가 중개사와 계약·과금하고, 호스트는 StaySync 화면에서 자기 에어비앤비 계정을 연결한다 | StaySync 하나 | Channex, Rentals United, ONDA(공급 파트너 API) |
| **호스트 계정형 PMS + Open API** | 호스트가 그 PMS 를 구독하고, StaySync 는 그 계정의 API 를 읽고 쓴다 | StaySync + 그 PMS | Guesty |

**"다른 사이트에 비해 메리트"는 앞 부류에서만 나온다.** 뒤 부류는 호스트가 이미 쓰는
PMS 위에 StaySync 를 한 겹 더 얹는 모양이라, 그 PMS 가 하는 일을 StaySync 가 반복한다.

## 3. 후보별로 확인한 것 (2026-09-17)

### Channex

| 항목 | 내용 |
|---|---|
| 에어비앤비 | 에어비앤비 파트너 페이지에 Preferred+ 로 게재 |
| 채널 | 요금 페이지 기준 68개. 채널별 요금·등급별 제한 없음. 아고다·트립닷컴·익스피디아 있음 |
| 국내 OTA | **채널 코드 목록에 없음** (야놀자·여기어때·네이버·인터파크·마이리얼트립·위홈) |
| 요금 | 플랫폼 월 $130 · 휴가용 임대 유닛당 $0.50 · 호텔 숙소당 $7 · 셋업비 없음 · 월 과금, 언제든 해지. **조사-01(08-24)과 같다** |
| 부가 기능 | 메시징·리뷰가 유닛당 $0.50 별도. **인박스에 에어비앤비 메시지를 받으려면 이것이 필요하다** |
| 에어비앤비 시험 | 샌드박스 계정이 없다. **실제 호스트 계정과 게시 리스팅으로 시험한다.** 가짜 리스팅은 계정 차단 위험, 실제 리스팅은 시험하는 동안만 연결하라고 적혀 있다. 매핑 전에 요금·최소 숙박이 맞는지 보라고 권한다 |
| 상용 전환 | 인증 14항목 + **화면 공유 검토.** 변경을 감지하는 구조(DB 폴링 루프 불가), 아웃박스·배치로 분당 20 ARI, 429·5xx 재시도, **전체 동기화는 24시간에 한 번까지**, 합성 데이터로 보이면 일정을 잡기 전에 거절 |

**우리 설계와 맞는 곳.** 아웃박스, ARI 병합 버퍼, 레이트 리밋 대응은 조사-01 5절에서
인증 항목과 대조해 뒀다.

**새로 걸리는 곳 둘.**

- **화면 공유에서 "테스트 스크립트가 아니라 실제 사용자 조작에 반응하는지"를 본다.**
  숙소·요금 등록 화면이 없으면 요금을 API 로 넣어야 하는 지금 구조는 이 검토에 약하다.
  2차로 미뤘던 등록 화면이 판매 경로에서는 인증 조건이 된다
- **"전체 동기화 24시간 1회"와 우리 정기 재동기화 주기**를 대조해야 한다(측정-03)

### ONDA (온다)

| 항목 | 내용 |
|---|---|
| 성격 | 국내 호스피탈리티 테크. 에어비앤비 우수 파트너 선정 보도가 있다 |
| 채널 | FAQ 기준 75개. 에어비앤비·부킹닷컴·아고다·트립닷컴 등 글로벌과 **여기어때·네이버·쿠팡·카카오** 등 국내 |
| 외부 개발사 | 공급(Vendor) 파트너로 API 22개 + 웹훅 5개를 구현하면 라이브. 기간은 FAQ 가 "평균 1~2주", 개발자 센터가 "평균 1개월"로 **서로 다르다** |
| 접근 | 파트너 유형 확인 → **계약 및 인증 정보 발급** → 개발 → 시험·오픈. 가입 즉시 쓰는 스테이징은 찾지 못했다 |
| 요금 | 매장 수·약정 기간·채널 구성에 따른 견적 |
| 주의 | **ONDA Plus 가 펜션·게스트하우스용 채널매니저·PMS·부킹엔진·AI 응대 올인원이다.** 우리와 같은 고객층을 노리는 제품이기도 하다 |

### Guesty

| 항목 | 내용 |
|---|---|
| Lite | **1–3 리스팅용.** 리스팅당 월 $9부터, 14일 체험. 채널 셋(에어비앤비·부킹닷컴·Vrbo). Open API 는 "select integrations" — StaySync 같은 외부 앱이 들어가는지 불명 |

### Rentals United

화이트라벨 연동 API. 에어비앤비 포함 50+ 채널, **XML 전용**, 연동 개발 1~3개월, 가격 비공개.
학기 일정에 비해 무겁고 Channex 보다 나은 점을 찾지 못했다.

## 5. 시험 순서 제안 — 업체 허락이 먼저다

1. **업체 허락.** 어느 리스팅, 어느 기간, 무엇을 써도 되는지(재고만인지, 요금도인지).
   교수 보고서 8절 2번의 질문을 이 내용으로 바꿔 드리는 편이 정확하다
2. **리스팅 하나를 Channex 스테이징에 연결·매핑한다.** 연결 전에 에어비앤비 쪽 요금·최소
   숙박이 맞는지 본다(Channex 권고)
3. **그 판매 단위의 iCal 연결을 먼저 끈다.** 같은 리스팅에 iCal 과 Channex 가 함께 붙으면
   같은 예약이 채널 코드만 다르게 두 번 들어온다. `uq_channel_booking` 은
   `(channel_code, channel_booking_id)` 라 이것을 막지 못하고, 초과 판매 충돌로 뜬다
4. **받기만 먼저.** Channex 로 들어온 예약이 iCal 로 받던 건수·박수와 같은지 대조한다
5. **좁게 내보내기.** 먼 미래 하루의 판매 중지 → 에어비앤비 달력 반영 확인 → 되돌리기.
   요금은 그다음
6. **끝나면 매핑을 해제한다**(Channex 권고). 상시 연결은 판매 단계에서 정한다

## 6. 착수 전에 확인할 것

- ~~교수가 말한 서비스가 어느 곳인지~~ — Channex 로 확인됐다(09-17)
- ~~Channex 예약 데이터에 금액이 오는지~~ — 우리 쪽 금액 통로(`InboundBooking.totalAmount`)는 있다.
  어댑터가 응답의 금액을 넣으면 된다. **iCal 예약은 계속 금액이 없으므로 리포트 수정은 따로 필요하다**
- ~~Channex "전체 동기화 24시간 1회" 조건과 우리 재동기화 주기~~ — 하루 한 번 04:00 이라 맞는다(검토-01 3절 6번)
- 에어비앤비 연결에 호스트 쪽 조건이 있는지 — 외부 비교 글 한 곳이 "전문 호스트 등록이
  필요하다"고 적었으나 공식 문서로 확인하지 못했다
- ONDA — 공급 파트너 API 로 에어비앤비 배포까지 되는지, 학기 프로젝트와 계약하는지,
  개발 기간 표기 불일치
- 판매 단계 원가 — Channex 월 $130 고정비를 몇 유닛에서 넘기는지는 판매 가격이 정해진
  뒤에 계산한다
