# 조사 03. Guesty — 에어비앤비 연동 대안으로 쓸 수 있는가

- 조사일: 2026-09-11
- 계기: 지도교수가 "에어비앤비 공식 API 는 기간이 오래 걸리고 잘 승인되지 않으니
  Guesty 를 이용해 보라"고 제시
- 관련: 조사-01(Channex), 조사-02(에어비앤비 iCal), 계획서 3.3 / 10.2 / 10.3

**결론 — Guesty 는 막혀 있는 문제를 풀어 주지 않는다. 다만 다른 이유로 값이 있다.**

---

## 1. Guesty 가 무엇인가

숙박 위탁운영사와 전문 호스트를 위한 상용 PMS 다. **우리가 만들고 있는 것과 같은
자리의 제품**이고, 에어비앤비·부킹닷컴·Vrbo 에 공식 채널 연결을 가지고 있다.
Open API 를 열어 두어 외부 시스템이 Guesty 안의 리스팅·예약·캘린더를 읽고 쓸 수 있다.

즉 우리가 쓴다면 **StaySync ← Guesty Open API → 에어비앤비** 모양이 된다.
계획서 3.3 이 Channex 에 맡긴 자리와 같다.

## 2. 확인한 사실

| 항목 | 확인 결과 |
|---|---|
| 무료 티어 | **없다.** Lite 가 리스팅당 월 $9 부터, 14일 체험이 있다 |
| Open API 포함 여부 | 세 플랜 모두 포함. Lite 는 "select integrations" |
| 자격증명 발급 | **Guesty 계정 안에서 앱을 등록해 받는다.** 계정이 먼저 있어야 한다. OAuth 앱은 최대 5개 |
| 샌드박스 | **고객 담당자(CSM)나 Customer Solutions 에 요청해야 한다.** 문서에 "토큰 수수료가 부과될 수 있다"고 적혀 있고 Booking Engine API 하나로 제한된다 |
| 승인 기간 | 문서에 없다 |

**샌드박스가 CSM 을 거친다는 것은 이미 고객이라는 뜻이다.** 계정 없이 개발자가 바로
받아 볼 수 있는 경로는 문서에서 찾지 못했다.

## 3. 막힌 것은 API 가 아니라 리스팅이다

**에어비앤비가 막힌 이유는 승인 절차가 아니다.** 확인-04·05 와 계획서 12.2 에 적어
둔 대로다.

- 리스팅을 게시하려면 **대한민국 숙박업 영업신고증**이 필요하다
- 미게시 리스팅은 전 기간이 이미 하나의 차단 일정이라 **개별 예약을 구분할 수 없고
  열린 날짜가 없어 날짜가 닫히는 변화를 볼 자리도 없다**

**Guesty 는 자기가 관리하는 에어비앤비 계정에 붙는 것이지 리스팅을 만들어 주지
않는다.** 게시된 리스팅이 없으면 Guesty 를 거쳐도 실제 예약은 들어오지 않는다.
같은 제약이 그대로 남는다.

Guesty 샌드박스의 가짜 리스팅·예약으로 시험할 수는 있는데, **그것은 6.4 의 Mock OTA
시뮬레이터가 이미 하고 있는 일이다.**

## 4. 이미 같은 자리에 Channex 가 있다

조사-01 에 적어 둔 대로다.

| | Channex 스테이징 | Guesty |
|---|---|---|
| 비용 | 무료 | 유료. 14일 체험 |
| 발급 | 가입 즉시 API 키, 카드 불필요 | 계정 필요. 샌드박스는 담당자 요청 + 수수료 가능 |
| 테스트 숙소 | 부킹닷컴 공용 테스트 숙소 제공 | 샌드박스 별도 |
| 우리 코드 | **13주차에 어댑터로 이미 붙였다** | 없다 |

목적이 같은데 하나는 무료로 이미 돌고 있다.

## 5. 그래도 값이 있는 쪽 — 어댑터를 하나 더 붙이는 일로 보면

"에어비앤비 우회로"가 아니라 **어댑터 추가**로 보면 얘기가 달라진다.

어댑터 구조는 이미 서 있다 — 레지스트리, `AdapterType` 의 capability 선언,
`AdapterContractTest`. **상용 API 를 하나 더 꽂아 보는 것은 그 설계가 실제로 열려
있다는 증명**이고, 발표에서 "Mock·iCal·Channex·Guesty 넷이 같은 인터페이스로
꽂힌다"는 그림이 된다. 계획서 1.4 의 기술적 초점과 결이 맞다.

비용은 14일 체험 + 리스팅 1개면 학기 프로젝트가 감당할 수준이다.

**다만 10월 말 배포와 P5 AI 를 하면서 곁들일 일은 아니다.** 넣는다면 P6 다.

## 6. 교수께 드릴 정리

시연이 아니라 사실만 옮긴다.

1. Guesty 는 무료 티어가 없고 Open API 자격증명은 계정 안에서 발급되며, 샌드박스는
   고객 담당자를 거치고 수수료가 붙을 수 있습니다
2. 에어비앤비가 막힌 이유는 API 승인이 아니라 게시할 리스팅이 없다는 것이고
   (숙박업 영업신고증), 이 제약은 Guesty 를 거쳐도 그대로입니다
3. 같은 목적의 Channex 스테이징은 무료이고 13주차에 이미 붙여 두었습니다
4. 그래서 Guesty 는 "에어비앤비 대안"이 아니라 **어댑터를 하나 더 붙여 설계의 개방성을
   보이는 용도**로 P6 에 넣는 편이 맞다고 봅니다. 교수님 판단을 구합니다

**업체가 게시된 리스팅을 하나 내주는 편이 Guesty 보다 확실하다.** 시연-01 5절에
적어 둔 그대로이고, 그러면 P3 완료 조건 셋째의 미판정 부분이 실제로 닫힌다.
