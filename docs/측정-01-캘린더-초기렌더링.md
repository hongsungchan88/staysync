# 측정 01. 캘린더 초기 렌더링

- 측정일: 2026-09-03
- 범위: P2 7주차, 작업지시 04 완료 조건 13
- 목표: 계획서 8.2 — 30객실 × 90일, 2,700셀 초기 렌더링 **1초**

측정만 하고 결과를 그대로 적는다. 8주차 범위를 정하는 근거로 쓴다.

---

## 조건

| 항목 | 값 |
|---|---|
| 판매 단위 | 30개 (`객실 01`~`객실 30`, 각 `total_units` 1) |
| 기간 | 90일 |
| 셀 | 2,700개 |
| 예약 막대 | 90개 (판매 단위당 3건, 3박씩) |
| 응답 크기 | 296 KB (전송 258 KB) |
| 백엔드 | `local` 프로파일, 내장 PostgreSQL 16 |
| 프론트 | Vite 6 **개발 서버**, React 19 `StrictMode` |
| 브라우저 | 내장 브라우저 페인 |

**측정 환경의 한계를 먼저 적는다.** 개발 서버라 모듈이 번들되지 않은 채 각각 로드되고,
`StrictMode` 는 개발 모드에서 컴포넌트를 두 번 렌더한다. 프로덕션 빌드는 이보다 빠르다.
아래 수치는 **개발 환경 기준의 상한**으로 읽어야 한다.

## 서버 왕복 (Python 클라이언트, 브라우저 없음)

10회 반복.

| 구분 | 값 |
|---|---|
| 첫 호출 (cold) | 422 ms |
| 이후 중앙값 | **342 ms** |
| 최소 / 최대 | 296 ms / 485 ms |

모듈별 범위 쿼리 세 번(`inventory_ledger`, `rate_calendar`, `reservation`)과 조립을
합친 시간이다. 조인 한 문장으로 줄이지 않은 선택(ADR 없음, 작업지시 04 의 5절 5번)이
목표를 위협하지 않는다는 근거가 된다.

## 브라우저 초기 렌더링

페이지 로드 직후 타임라인(자원 타이밍).

| 구간 | 시각 |
|---|---|
| HTML + 모듈 로드 완료 | 77 ms |
| `POST /api/auth/refresh` | 99 → 264 ms |
| `GET /api/properties` | 284 → 416 ms |
| `GET /api/properties/1/calendar` | 430 → **713 ms** |

기간 이동 한 사이클(요청 → 2,700셀이 화면에 보일 때까지), 3회 중앙값.

| 구분 | 값 |
|---|---|
| 전체 사이클 | **996 ms** (991 / 996 / 997) |
| 그중 캘린더 API | 270 ms |
| 나머지 (파싱 + React 렌더 + 레이아웃 + 페인트) | **약 726 ms** |

DOM 규모.

| 항목 | 값 |
|---|---|
| DOM 노드 | 11,229개 |
| 그리드 크기 | 6,156 × 1,798 px |
| 강제 레이아웃 1회 | 130 ms |

## 판단

**목표 안에 들어오지만 여유가 없다.** 996 ms 대 1,000 ms 다. 개발 서버 기준이라
프로덕션 빌드에서는 더 나을 것이지만, 그걸 근거로 "달성했다"고 적지는 않는다.
측정하지 않은 값이다.

**느린 곳은 서버가 아니라 브라우저다.** 전체의 27%(270 ms)가 API 고 나머지 73%가
프론트엔드다. 서버 쿼리를 더 줄여도 전체는 크게 나아지지 않는다. 모듈 경계를 깨서
왕복을 하나 줄이는 선택이 지금 시점에 근거가 약하다는 뜻이기도 하다.

**병목은 DOM 크기다.** 셀 2,700개가 노드 11,229개를 만들고, 그 위에서 레이아웃 한 번이
130 ms 걸린다. 스크롤할 때마다 이 비용이 재현된다.

## 8주차에 대한 시사

가상 스크롤(`@tanstack/react-virtual`)이 이 측정의 직접적인 답이다. 화면에 보이는
30~40셀만 그리면 DOM 노드가 한 자릿수 백 개로 줄고, 레이아웃 비용도 그만큼 줄어든다.
7주차에 넣지 않은 이유는 **무엇이 느린지 알기 전에 최적화하지 않기 위해서**였고,
이제 수치가 나왔으므로 8주차 범위에 넣을 근거가 생겼다.

다시 측정할 때 비교할 기준값은 위 표 그대로다. 같은 조건(30객실 × 90일, 예약 90건,
개발 서버)에서 재야 의미가 있다.

## 재현 방법

```bash
# 백엔드
./gradlew bootRun --args='--spring.profiles.active=local'

# 데이터 주입과 서버 왕복 측정
python docs/scripts/seed_and_measure.py

# 프론트
cd frontend && npm run dev
# 브라우저에서 5173 접속 → 로그인 → 개발자 도구 Performance
```

`CalendarPage.tsx` 의 `WINDOW_DAYS` 는 7주차 기본이 30이다. 90일로 재려면 그 값을
임시로 바꾼다. 측정을 위한 설정을 코드에 남기지 않았다.
