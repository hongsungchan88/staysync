# 작업지시 21. 지니하우스를 iCal 에서 Channex 로 옮긴다 — 예약 갈아 끼우기, 인원, 원화 요금

- 작성일: 2026-09-24
- 작성: Cowork 세션 (문서·설계 담당, 34차)
- 대상: Claude Code (구현 담당)
- 범위: 인계메모 5절 순서 6. **10월 말 1차 심사 전에 끝낸다**
- 관련: 조사-04 5절(시험 순서), 작업지시-17(Channex 어댑터), 확인-10, 확인-11 4절 ③, ADR 0014

이 문서는 무엇을 만들지와 어떤 제약을 지킬지를 적는다. 어떻게 짤지는 적지 않는다.
5절의 결정은 착수 전에 정했다. 다시 열지 말 것.

새 세션이 이 문서로 시작한다면 CLAUDE.md 를 먼저 읽고 이 문서를 읽으면 된다.

## 1. 왜 필요한가

**교수 답(34차)** — "시험할 숙소와 무엇을 할지 알려 주면 숙소 호스트에게 통보하겠다. Channex 에 비용이 들면
알려 달라." 보고서 8절 2번의 막힘이 풀렸다. Cowork 이 **홍대 지니하우스**를 제안했다 — 세 리스팅 중 앞으로 예약이
가장 적고(09-23 기준 앞 100일 13건·48박) 숙소 하나에 리스팅 하나라 가장 단순하다. 비용은 0원이다(Channex 스테이징 +
실제 에어비앤비 계정이 Channex 가 안내하는 시험 방식이다).

**지금 그대로 붙이면 안 된다.** 지니하우스의 앞으로 예약은 iCal(`AIRBNB_ICAL`)로 들어와 있다. Channex 를 붙이면
에어비앤비가 **같은 예약을 금액·이름·인원까지 붙여 다시** 넘겨준다. 채널 코드가 달라(`uq_channel_booking` 이
`(channel_code, channel_booking_id)` 다) 새 예약으로 들어오고, 예약된 밤마다 초과 판매 충돌이 뜬다(조사-04 5절 3번).

**이게 끝나면 심사에서 달라지는 것** — 지니하우스 예약에 금액·손님 이름·인원이 붙는다. 지금 리포트의 "금액 미상"과
캘린더의 `이름 없음(iCal)` 이 그 판매 단위에서는 사라진다. 에어비앤비 쪽으로 요금·예약 가능 날짜를 내보내는 것도
처음으로 실제 리스팅에서 돈다 — 조사-04 가 말한 "차별점"이 실물이 된다.

## 2. 이번에 만드는 것

### A. 예약 갈아 끼우기

Channex 로 새 예약이 들어올 때, **같은 판매 단위에 체크인·체크아웃이 똑같은 살아 있는 iCal 예약이 있으면 새로
만들지 않고 그 예약을 Channex 예약으로 바꾼다.**

- 예약 id 는 그대로다. **재고 원장은 움직이지 않는다**(같은 밤을 같은 예약이 계속 잡는다)
- 채널 코드·채널 예약 id 를 Channex 쪽 값으로 바꾸고, 금액·손님 이름·인원을 채운다
- 감사 행을 남긴다 — 무엇이 무엇으로 바뀌었는지
- 날짜가 하나라도 다르면 갈아 끼우지 않는다. 기존 경로대로 새 예약 → 충돌 카드. 사람이 정리한다
- 대상은 "살아 있는" iCal 예약이다. 취소·만료된 것은 대상이 아니다. 체크인한 예약을 포함할지는 조사 뒤 8절에 적는다

**이게 공백 없이 되는 이유.** 같은 판매 단위에 iCal 과 Channex 를 동시에 매핑하면 409 로 막힌다
(`MAPPING_DOUBLE_INTAKE`, 작업지시-17 브랜치 1). 그래서 전환은 반드시 **iCal 매핑 해제 → Channex 매핑** 순서다.
iCal 매핑을 풀어도 **이미 받은 예약은 캘린더에 남아 재고를 계속 잡는다**(20 의 매핑 해제 확인 문구 그대로).
Channex 가 같은 예약을 넘겨주는 순간 그걸 갈아 끼우므로, 그 사이에 날짜가 열리지 않는다.

### B. 채널 예약의 인원 — 확인-11 4절 ③

`ChannelBookingCommand` 에 인원 칸이 없어 채널 예약이 전부 기본값 성인 2 로 저장된다. Channex 어댑터는
`occupancy.adults` 를 읽는데 경계에서 떨어진다 — 15주차 `guestName` 과 같은 모양이다. **호출자를 다 훑고 원인 자리에서
한 번 고친다**(인계메모 6절 "절반만 고치고 닫은 결함"). 고치면 예약 패널이 채널 예약에도 인원을 보인다(20 의 9절에서
직접예약에만 보이게 해 둔 것을 푼다).

### C. 에어비앤비가 두 채널로 갈라져 보이지 않게

Channex 로 들어오는 에어비앤비 예약에 붙일 채널 코드를 정한다. 지금 Channex 연결은 채널 코드를 연결 단위로 박는다
(`connection.getChannelCode()`, `ota_name` 은 읽지 않는다). 지니하우스용 Channex 숙소에는 에어비앤비 하나만 붙이므로
연결의 채널 코드로 충분하다 — **`ota_name` 으로 가르는 일은 이번에도 하지 않는다.**

- 캘린더 막대의 라벨·색이 iCal 로 받던 에어비앤비와 같아야 한다. 회색으로 떨어지면 안 된다(6절 되풀이 목록)
- **리포트 채널 믹스에서 에어비앤비가 두 줄로 갈라지지 않는다.** 업체 눈에는 같은 에어비앤비다
- 코드 이름은 구현이 정한다. 8절에 적는다

### D. 원화 요금 전송 형식

지니하우스 요금은 원화다. 지금 어댑터는 요금을 `"120.00"` 처럼 소수 둘째 자리 문자열로 보낸다(USD 로 실측).
Channex 문서는 "소수 문자열(`"200.00"`) 또는 **통화 최소 단위 정수**(USD 200.00 → `20000`)" 두 방식을 적고, 원화처럼
소수가 없는 통화는 말하지 않는다. 확인-10 에 "정수 `10000` 으로 요금제를 만들었더니 최소 단위로 읽혔다"는 실측이 있다.

- **스테이징의 원래 KRW 개발 숙소(`2aacda1a-…`, 확인-10 1절)에서 실측으로 정한다.** `170000` 을 보내고 되읽어
  `170000` 이 나오는 형식을 쓴다. `"170000.00"`·`170000`·`"170000"` 을 각각 보내 되읽은 값을 확인-12 에 표로 남긴다
- 틀린 형식은 **100 배 또는 1/100 로 조용히 들어간다.** 200 + 경고가 아니다. 그래서 되읽기 없이 정하지 않는다
- 통화별 분기가 필요하면 숙소 통화를 보고 가른다. 지금 숙소 통화는 KRW 고정이다

### E. 로컬 리허설 — 호스트 없이 전환을 끝까지 돌려 본다

실제 전환(9절)은 되돌리기 어렵다. 그 전에 로컬에서 같은 모양을 재현한다.

1. 로컬 조직에 판매 단위 하나, iCal 예약 셋을 만든다(날짜 다르게)
2. iCal 매핑을 해제한다 → 예약 셋이 캘린더에 남는지, 재고가 그대로인지 본다
3. Channex 매핑을 건다
4. **Booking CRS**(확인-10 3.2)로 `ota_name "Airbnb"` 예약을 만든다 — 둘은 iCal 예약과 날짜가 같게, 하나는 하루 어긋나게
5. 같은 둘은 갈아 끼워지고(예약 id 그대로, 금액·이름·인원 채워짐, 재고 불변), 어긋난 하나는 충돌 카드로 뜨는지 본다
6. **이어서 변경·취소를 Booking CRS 로 보내**, 갈아 끼운 예약이 Channex 의 변경·취소를 제대로 따라가는지 본다

### F. 전환 뒤 대조 — 확인 문서에 쿼리로

- **전환 뒤 남은 앞으로 iCal 예약 수**를 세는 쿼리. 0 이어야 한다. 남으면 Channex 가 그 예약을 안 넘겨준 것이고,
  그 예약은 앞으로 변경·취소를 받을 길이 없다 — 사람이 에어비앤비 화면과 맞춰 본다
- **Channex 가 연결 직후 기존 예약을 넘겨주는지는 문서에 없다.** 우리 부킹닷컴 채널 응답에 `actions:
  ["load_future_reservations"]` 가 있었다(확인-10 1.1). 안 넘어오면 그 액션으로 불러오는 절차를 확인 문서에 적는다

## 3. 이번에 만들지 않는 것

- **`ota_name` 으로 채널 코드를 가르는 일.** 지니하우스용 Channex 숙소에는 에어비앤비만 붙인다
- **iCal `DESCRIPTION` 에서 예약 코드를 읽어 잇는 방식.** 가장 정확하지만 "`DESCRIPTION` 은 읽지 않는다"(계획서 15.3)를
  다시 연다. 5절 1번
- 원화 외 통화 표시(확인-11 4절 ④), 없는 경로 500(⑦) — 순서 10
- 메종드서촌 2층·3층의 전환. 지니하우스가 돌고 업체가 원하면 같은 절차로 한다
- 메시지·리뷰 연동(Channex 부가 기능, 유닛당 $0.50 별도). 인박스에 에어비앤비 메시지는 아직 안 들어온다

## 4. 지켜야 할 제약

- **배포 환경의 `1차 심사` 데이터는 9절(실제 전환) 전까지 바꾸지 않는다.** 1~8절은 로컬과 스테이징에서 끝낸다
- **API 키·iCal 주소·게스트 개인정보를 문서·로그·커밋에 남기지 않는다.** 실제 전환 뒤 들어오는 손님 이름·인원은
  ADR 0007(게스트 개인정보 암호화) 경로로만 저장된다
- 우리 쪽 전송 상한은 문서 값(숙소당 분당 10) 그대로다(`ChannexSendLimiter`)
- 갈아 끼우기는 **재고 원장을 움직이지 않는다.** 원장 행 수와 `booked_units` 가 전후 같아야 한다 — 테스트로 박는다
- 마이그레이션이 생기면 배포 전 덤프와 되돌림 방법을 8절에 적는다

## 5. 착수 전에 정한 것

1. **잇는 방식은 "같은 판매 단위 + 같은 체크인·체크아웃"이다**(사용자, 34차). 예약 코드로 잇는 방식은 택하지 않는다 —
   `DESCRIPTION` 을 열어야 한다. Hostaway 는 iCal 을 끊으면 그 예약을 지우고 API 가 다시 들여오게 하는데, 우리 방식은
   같은 끝 상태를 **날짜가 열리는 공백 없이** 만든다. 1실 숙소라 같은 날짜에 예약이 둘일 수 없어 사실상 정확하다
2. **시험 숙소는 지니하우스 하나**(교수께 제안, 34차)
3. **Channex 쪽은 지니하우스 전용 숙소를 새로 만든다.** 원래 KRW 개발 숙소는 D 의 실측에만 쓰고 건드리지 않는다
4. **ADR 은 만들지 않는다.** 갈아 끼우기는 1회성 전환 규칙이고 이 문서 5절이 기록이다

## 6. 완료 조건

1. 같은 판매 단위·같은 날짜의 살아 있는 iCal 예약이 Channex 예약으로 **갈아 끼워진다** — 예약 id 그대로, 금액·손님
   이름·인원 채워짐, 감사 행 남음
2. 날짜가 하루라도 다르면 갈아 끼우지 않고 충돌 카드로 간다
3. 갈아 끼우기 전후 **원장 행 수·`booked_units` 가 같다**(테스트)
4. 갈아 끼운 예약이 **이후 Channex 변경·취소를 따라간다**
5. 채널 예약의 인원이 저장되고 예약 패널에 보인다(직접예약만 보이던 제한을 푼다)
6. Channex 로 들어온 에어비앤비 예약이 캘린더에서 iCal 에어비앤비와 **같은 라벨·색**이고, 리포트 채널 믹스에서
   **한 줄**이다
7. 원화 요금 전송 형식을 **스테이징 되읽기로** 정했다 — 세 형식의 되읽은 값이 확인-12 표에 있다
8. **로컬 리허설(2절 E) 여섯 단계**를 끝까지 돌렸다
9. 전환 뒤 남은 앞으로 iCal 예약을 세는 쿼리와, 기존 예약이 안 넘어올 때의 `load_future_reservations` 절차가
   확인-12 에 있다
10. 테스트 전체 통과, 배포, 번들 해시 셋 일치. **배포로 `1차 심사` 데이터가 바뀌지 않았다**(예약·원장 수 전후 같음)

## 7. 순서와 기록

한 브랜치로 간다(`feat/channex-airbnb-switch`). 기록은 **확인-12** 에 남긴다 — 1절 원화 요금 실측, 2절 로컬 리허설,
3절 실제 전환(9절 뒤), 4절 대조.

## 9. 실제 전환 — 사람과 함께, 1~8 이 끝난 뒤

**Claude Code 혼자 하지 않는다.** 호스트 승인이 필요하고, 순서마다 Cowork 과 사용자가 확인한다.

1. **호스트에게 받는다** — 지금 에어비앤비에 설정된 요금(평일·주말)과 최소 숙박. 다른 채널 매니저가 붙어 있는지
2. **StaySync 지니하우스 요금·최소 숙박을 그 값에 맞춘다.** 연결되면 Channex 가 매일 에어비앤비를 우리 값으로 덮는다
3. Channex 지니하우스 숙소에 재고·요금을 먼저 내보낸다(되읽기로 확인)
4. **iCal 매핑 해제**(20 의 확인 단계를 거친다) → Channex 매핑
5. **호스트가 에어비앤비 연결을 승인한다**(Channex 공유 링크. 비밀번호는 받지 않는다)
6. **받기만 먼저** — 기존 예약이 넘어와 갈아 끼워지는지, 남은 iCal 예약이 0 인지 대조한다(조사-04 5절 4번)
7. **좁게 내보내기** — 먼 미래 하루 판매중지 → 에어비앤비 달력에서 확인 → 되돌리기. 요금은 그다음
8. 심사가 끝나면 매핑을 해제할지 업체와 정한다(Channex 권고는 시험이 끝나면 해제). 해제하면 스마트 요금 등은 호스트가
   다시 켜야 할 수 있다

**호스트에게 보낼 안내는 Cowork 이 쓴다**(연결 방법, 연결 동안 요금·날짜가 덮인다는 것, 스마트 요금·프로모션이
꺼진다는 것, 해제 방법).
