## 1. 왜 필요한가

Cowork 이 업체용 써 보기 안내를 쓰다가(10-20) 심사자가 새로 가입한 계정에서 막히는 자리 둘을 찾았다.

1. **위젯 주소가 앱 어디에도 없다.** 직접예약 위젯은 `/widget/{숙소 id}` 인데 숙소 화면·캘린더 어디에도 링크가 없다(배포 환경 DOM 확인).
   새 계정 심사자는 자기 숙소의 위젯을 찾을 수 없다 — StaySync 가 앞선다고 내세우는 기능(직접예약·결제)이다
2. **예약을 화면에서 입력할 길이 없다.** 서버 `POST /api/reservations` 는 있으나 화면이 부르지 않는다. 새 계정에는 채널이 없으므로
   예약이 생기는 길이 위젯 실결제뿐이다 — 그래서 체크인·체크아웃·청소 카드·리포트를 결제 없이는 해 볼 수 없다. 전화·현장 예약을
   적어 두는 것은 숙소 운영 도구의 기본이기도 하다

## 2. 이번에 만드는 것

### A. 숙소 화면에 예약 위젯 주소

- 숙소마다 "예약 위젯" 주소(전체 URL)와 **열기**(새 탭)·**주소 복사**
- 주소는 서버 `.env` 의 `PUBLIC_BASE_URL` 기준(배포 = `https://staysync.kr`). 화면이 `location.origin` 을 쓰는 것으로 충분하면 그렇게(새 설정 없이)
- 판매 단위가 없거나 요금이 없어 위젯이 팔 것이 없으면 그 사실을 한 줄로(위젯이 빈 화면이 되지 않게 — 위젯 쪽 문구가 이미 있으면 그대로)

### B. 캘린더에서 예약 입력

- 캘린더에서 들어가는 "예약 추가" — 판매 단위, 체크인·체크아웃, 게스트 이름, 성인·아동, 금액
- 기존 `POST /api/reservations` 를 쓴다. 요청 모양이 이 화면에 모자라면(예: 금액) 무엇을 더했는지 8.1 에 적는다
- 채널은 **직접예약(`DIRECT`)**. 그래서 작업지시-26 의 끌어 옮기기·취소가 그대로 된다
- 금액 — 비워 두면 요금표로 계산한 값(위젯과 같은 계산)을 쓰거나 미리 채워 보인다. 사람이 고친 값이 있으면 그 값. 어느 쪽인지 8.1 에 적는다
- 재고가 없거나 최소 숙박에 걸리면 서버의 기존 문구를 그대로 보인다(중복예약 방어는 서버가 한다 — 화면이 미리 막는 것은 보조)
- 만든 뒤 캘린더 막대가 바로 생기고(실시간 갱신 그대로), 예약 패널에서 체크인 → 체크아웃 → 청소 카드까지 이어진다
- 확인 단계는 화면 안(모달 없음). 문구는 담백하게

## 3. 이번에 만들지 않는 것

- 결제 링크 보내기·선결제, 예약 확인 메일·문자
- 채널 예약을 손으로 만드는 것(`DIRECT` 만)
- 게스트 목록·재방문 손님 찾기
- 위젯 꾸미기(숙소 이름 표시 포함 — 화면 점검 ③, 심사 뒤)

## 4. 지켜야 할 제약

- **배포 환경 업체 데이터(`1차 심사` 조직)를 바꾸지 않는다.** 확인은 로컬과 배포 환경의 `온보딩 시험 조직`
- 마이그레이션은 생기지 않을 것으로 본다. 생기면 8.2 에 덤프·되돌림
- 게스트 이름은 기존 개인정보 암호화(`PersonalDataCipher`) 경로를 그대로 탄다 — 새 저장 경로를 만들지 않는다
- 테스트는 실제 진입점 — HTTP 로 만들고 원장·감사·이벤트를 DB 로 본다. 재고 0 인 날 400/409 와 원장 그대로
- 브라우저 모달·새 의존성 없음. 번들 해시가 바뀌므로 셋 일치 확인

## 5. 착수 전에 정한 것

1. **A·B 둘 다 심사 전(사용자, 10-20)**
2. 손으로 입력한 예약은 `DIRECT`
3. 배포는 사용자 승인 뒤

## 6. 완료 조건

1. 숙소 화면에 숙소마다 위젯 주소·열기·복사가 있고, 열면 그 숙소 위젯이 뜬다
2. 테스트 — 예약 입력 API: 성공 시 예약 `DIRECT`·CONFIRMED(또는 기존 생성 규칙의 상태), 원장 확보, 감사 1. 재고 없음·최소 숙박 위반은 거절·원장 그대로
3. 프론트 테스트 — 예약 추가 폼이 요청을 올바르게 만든다(금액 비움/입력 둘), 서버 오류 문구를 보인다
4. 로컬 화면 — 예약 추가 → 막대 생김 → 체크인 → 체크아웃 → 청소 카드 생김
5. 백엔드·시뮬레이터·프론트 전체 통과
6. 배포 — 행 수 같음, 번들 셋 일치, 5분 로그 0. **배포 환경 확인은 Cowork 이 `온보딩 시험 조직` 에서** — 위젯 주소, 예약 추가 → 체크인 → 체크아웃 → 청소 카드
   (그 조직 로그인은 사용자가 한다. 업체 조직에서는 숙소 화면에 위젯 주소가 보이는 것만 본다)
