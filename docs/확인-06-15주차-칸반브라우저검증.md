## 1. 확인 절차

"체크아웃하면 태스크가 생긴다"를 처음부터 보기에 낫다.

```
숙소 Week15 Stay(id=3) → 판매 단위 Room 01(id=33)
예약 128 (2026-09-06 ~ 09-08) → 체크인 → 체크아웃
```

**체크아웃 3초 만에 태스크가 생겼다.** 릴레이 주기가 1초이므로 그 사슬이 실제로
돈다는 뜻이다.

| 본 것 | 결과 |
|---|---|
| `/ops/tasks` 목록 | 할 일 칸에 1건. `Room 01` |
| 기한 | `2026-09-08 11:00 ~ 열림` (다음 예약 없음) |
| 드래그로 진행 중 이동 | 서버 `status=IN_PROGRESS` |
| 드래그로 완료 이동 | `status=DONE`, `completedAt` 채워짐 |
| 판매 단위 청소 상태 | 체크아웃 직후 `DIRTY` → 완료 후 `CLEAN` |

**드래그가 실제로 동작한다.** 단위 테스트는 칸 선택 목록 쪽만 볼 수 있어(jsdom 에서
dnd-kit 의 좌표 계산이 돌지 않는다) 이 경로는 여기서만 확인된다.

## 2. 결함 하나 — 기한이 9시간 어긋나 보였다

```
화면:      2026-09-08 02:00 ~ 열림
있어야 할 값: 2026-09-08 11:00 ~ 열림
```

서버는 `2026-09-08T02:00:00Z` 로 보낸다. 화면이 그 ISO 문자열을 **앞에서 16자 잘라**
쓰고 있었다. 시간대를 무시하므로 체크아웃 11시가 새벽 2시로 뜬다.

**단위 테스트는 통과하고 있었다.** 픽스처의 시각을 `+09:00` 으로 적어 두어 자르기가
우연히 맞아떨어졌다. 픽스처를 서버가 실제로 보내는 `Z` 형태로 바꾸고, 지역 시각으로
옮겨 적도록 고쳤다. 고치기 전 코드로 되돌려 새 테스트가 실패하는 것을 확인했다.

**픽스처를 실제 응답과 다르게 적으면 그 테스트는 아무것도 보증하지 않는다.**
10주차의 `nullish` 건과 같은 모양이다 — 그때도 화면이 통째로 오류가 났는데 테스트는
통과였다.

## 3. 결함 둘 — 확인-05 의 D 가 절반만 고쳐져 있었다
