## 4. 발견만 하고 안 고친 것

1. **잘못 누른 체크인·체크아웃을 되돌릴 수 없다.** 패널에 되돌리기 버튼이 없고, 서버 상태 전이가 앞으로만 간다
   (`Reservation.checkIn`·`checkOut`). 체크아웃을 잘못 누르면 예약은 `CHECKED_OUT` 으로 굳고 청소 태스크와
   인박스 알림이 이미 생겨 있다. 태스크는 칸반에서 옮길 수 있지만 예약 상태는 사람이 못 고친다. 버튼 하나라
   한 번의 오조작이면 된다 — 확인 단계도 없다
2. **매핑 해제는 한 번 누르면 바로 지워진다**(`ChannelMappingPage`, 확인 없음). iCal 매핑에는 **발행 토큰이 붙어
   있어**(`channel_mapping.export_token`) 해제하면 에어비앤비에 등록해 둔 우리 발행 주소가 죽는다. 다시 매핑하면
   토큰이 새로 생겨 에어비앤비 쪽 등록도 다시 해야 한다. 채널 쪽 식별자는 화면에 보이므로 매핑 자체는 되살릴 수 있다
3. **채널 수신이 인원을 넘기지 않는다.** `ChannelBookingCommand` 에 인원 칸이 없어 채널 예약은 전부 기본값 성인 2
   로 저장된다. Channex 어댑터는 `occupancy.adults` 를 읽는데(`ChannexAdapter`) 경계에서 떨어진다 — 15주차
   `guestName` 과 같은 모양이다. 그래서 이번 패널은 직접예약에만 인원을 보인다. 확인-10 3.3 의 "성인 2" 는 우연히
   기본값과 같았던 것이다
4. **통화.** 패널 금액은 원으로 적는다. Channex USD 시험 숙소의 예약은 `361.08원` 으로 보인다 — 원화 외 통화는
   작업지시-20 3절 범위 밖이고, 배포 환경에는 CHANNEX 연결이 없다. 작업지시-21(원화 요금 전송)과 맞물린다
5. **충돌 해소의 "취소와 보상"** 은 고르고 `해소하기` 를 누르는 두 단계라 한 번에 눌리지는 않지만, 예약 취소가
   되돌릴 수 없다는 문구는 없다
6. 숙소·판매 단위에는 삭제가 없다(안전). 예약 패널에는 취소 버튼이 없다
7. 없는 API 경로(`/api/calendar`)와 경로 변수 형식이 틀린 요청(`/api/inbox/threads`)이 404·400 이 아니라 500
   `INTERNAL_ERROR` 다(3절 실측 중 경로를 틀려서 봤다). 화면이 부르는 경로가 아니라 업체에게는 안 보인다

### 5.1 고친 것 (브랜치 `feat/undo-transitions`)

| 자리 | 내용 |
|---|---|
| `Reservation.undoCheckIn`·`undoCheckOut(today)` | CHECKED_IN → CONFIRMED, CHECKED_OUT → CHECKED_IN. 뒤엣것은 오늘(Asia/Seoul)이 퇴실일을 넘으면 409 `CHECK_OUT_UNDO_EXPIRED` |
| `ReservationWriter.undoCheckIn`·`undoCheckOut` | 한 트랜잭션. 재고 안 건드림. 감사 `CHECK_IN_UNDONE`·`CHECK_OUT_UNDONE`, 뒤 값에 `reason` |
| `booking.CheckOutFollowUps` ← `ops.CheckoutTaskWithdrawal` | 청소 태스크가 TODO 면 지우고, 아니면 409 `CLEANING_ALREADY_STARTED`(상태 이름을 문구에) |
| `POST /api/reservations/{id}/check-in/undo`·`/check-out/undo` | 본문 `{reason}` 필수(1~200자, 공백만이면 400). 조직 확인은 다른 전이와 같은 `requireOwned` |
| `ReservationPanel` | 네 조작 모두 화면 안 확인 상자(`role="alertdialog"`) — 예약 이름·기간, 무엇이 따라 생기는지/거둬지는지. 되돌리기 둘은 사유 칸이 비면 확인 버튼이 안 눌린다. 체크아웃 되돌리기 버튼은 퇴실일이 지난 예약에는 없다. 서버 거절 문구는 그대로 |
| `ChannelMappingPage` | 매핑 해제 확인 상자. iCal 이면 발행 주소가 없어지고 다시 매핑하면 새 주소라 에어비앤비 쪽 등록을 바꿔야 한다는 문장 |
| `ConflictsPage` | "취소와 보상"을 고르면 "예약 취소는 되돌릴 수 없습니다." |

테스트: 서버 +8(`CheckInOutUndoTest` 6 — 체크인 취소·확정 예약 거절·할 일 거두기와 재체크아웃·진행 중 막기·이벤트보다
먼저 되돌리기·퇴실일 지남 / `ReservationApiTest` 2 — 사유 필수·남의 조직 404), 프론트 +7(패널 넷, 매핑 둘, 충돌 하나).
기존 패널 테스트 둘은 확인 단계를 거치도록 고쳤다.
