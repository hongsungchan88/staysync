## 1. 구성

| | |
|---|---|
| 서버 | AWS Lightsail, **Linux/Unix · Ubuntu 24.04 LTS · 2GB RAM / 2 vCPU / 60GB SSD**, 서울(ap-northeast-2) |
| 컨테이너 | app(JRE 21 + jar) · postgres(`pgvector/pgvector:pg16`) · caddy. **셋이다** — Redis 는 없다(아래) |
| 프록시·HTTPS | Caddy. Let's Encrypt 자동 발급·갱신 |
| 시크릿 | 서버의 `/opt/staysync/.env`, 권한 600 |
| 배포 | 개발 PC 에서 `deploy/push.sh user@host` |
| 도메인 | **`staysync.kr`** — 후이즈에서 2026-09-12 등록. 네임서버는 후이즈 기본, DNS 는 후이즈 관리 화면에서 |

**Redis 가 없는 이유.** 작업지시-15 는 넷을 적었지만 코드에 Redis 를 읽는 곳이 없다.
`UnitLock` 구현은 `LocalUnitLock` 하나이고 `build.gradle` 의 redis 의존성은 주석이다.
`staysync.lock.type` 도 아무도 읽지 않는다. 붙는 것이 없는 컨테이너를 2GB 에 올리지
않았다. 앱이 한 컨테이너뿐이라 JVM 락으로 충분하고, 인스턴스를 늘리는 순간 Redis 락
구현부터 필요하다.

**이미지를 서버에서 만드는 것처럼 보이지만 빌드는 개발 PC 다.** `deploy/app/Dockerfile`
은 `COPY staysync.jar` 뿐이다. `bootJar` 와 `npm run build` 는 push.sh 가 개발 PC 에서
돌리고, 서버의 `docker build` 는 레이어 하나를 더하는 일이라 메모리를 거의 쓰지 않는다.
2GB 에서 bootJar 를 돌리지 않는다는 4절의 제약을 이렇게 지킨다.

## 2. 서버 만들기 `[확인]` 2026-09-14

**실제로 만든 값.**

| | |
|---|---|
| 인스턴스 | `staysync` · Ubuntu 24.04 LTS · 2GB/2vCPU/60GB · 서울 `ap-northeast-2a` |
| 고정 IP | **`3.35.108.26`** (`staysync-ip`) |
| 방화벽 | SSH 22 · HTTP 80 · HTTPS 443(`Anywhere IPv4`). 5432·6379 없음 |
| 자동 스냅샷 | 켬. **UTC 00:00 = KST 09:00** — 낮에 돈다. 거슬리면 UTC 18:00 으로 옮긴다 |
| A 레코드 | `A staysync.kr → 3.35.108.26`. **후이즈가 1:1 상담으로 직접 넣어 줬다** |

**콘솔에서 걸린 것 둘.**

- **방화벽 규칙은 소스 IP 를 비우면 저장되지 않는다.** 프리셋에서 `Anywhere IPv4` 를
  골라야 `0.0.0.0/0` 이 채워진다
- **애플리케이션 드롭다운에 PostgreSQL·MySQL 이 있다. 고르지 않는다** — 5432 를
  인터넷에 여는 것이다

**DNS 전파에 2~24시간 걸릴 수 있다.** 후이즈 답변에 그렇게 적혀 있고 그동안 연결이
불안정할 수 있다. **퍼지기 전에 4절(첫 배포)로 가면 Caddy 가 인증서를 못 받는다.**

Lightsail 콘솔에서(다시 할 때의 절차):

1. **인스턴스 생성** — 리전 서울(ap-northeast-2), 플랫폼 Linux/Unix, 블루프린트 OS
   전용 **Ubuntu 24.04 LTS**, 플랜 **$12 (2GB RAM, 2 vCPU, 60GB SSD, 3TB 전송)**.
   SSH 키는 기본 키를 내려받아 `~/.ssh/` 에 둔다(권한 600)
2. **고정 IP** — 네트워킹 탭에서 고정 IP 를 만들어 인스턴스에 붙인다. 붙어 있는 동안
   무료다. **인스턴스를 지울 때 고정 IP 도 함께 지운다** — 떠 있는 고정 IP 는 요금이 붙는다
3. **방화벽** — 네트워킹 탭의 IPv4 방화벽을 **SSH 22, HTTP 80, HTTPS 443** 셋만 둔다.
   기본으로 22·80 이 열려 있으니 443 을 더한다. **5432·6379 는 만들지 않는다**
4. **자동 스냅샷** — 스냅샷 탭에서 자동 스냅샷을 켠다. 하루 한 번, 7일 보관.
   스냅샷 저장은 GB·월당 $0.05 이고 증분이라 실제로는 몇 GB 다
5. **DNS** — 후이즈의 **네임서버 고급설정 → A 레코드 관리(네임서버 호스팅)** 다.
   **루트 도메인은 호스트명을 공란으로 비운다.** 화면이 `[____].staysync.kr` 모양이라
   서브도메인 전용처럼 보이는데, 비우면 루트가 된다. 안내에 안 적혀 있어 후이즈에
   물어 확인했다(1:1 상담이 30분 답변보증이다).
   `nslookup staysync.kr` 이 고정 IP 를 돌려줄 때까지 기다린 뒤 4절로 간다 —
   Caddy 가 인증서를 받으려면 DNS 가 먼저 맞아야 한다.

   **`www` 를 걸지 않는다.** Caddy 의 `SITE_ADDRESS` 가 루트 하나이므로, `www` A 레코드만
   만들어 두면 그 이름으로 들어온 요청이 인증서를 못 받아 오히려 오류가 난다.
   `www` 도 쓰려면 A 레코드와 `SITE_ADDRESS` 를 **둘 다** 고쳐야 한다. 1차 심사에는
   루트 하나로 충분하다

## 3. 서버 준비 `[확인]` 2026-09-14

**먼저 DNS 를 봤다.** `nslookup staysync.kr` 이 KT 리졸버와 8.8.8.8 양쪽에서
`3.35.108.26` 을 돌려줬다(A 레코드 등록 이틀 뒤). 퍼지기 전에는 4절로 가지 않는다.

**키는 `~/.ssh/` 에 둔다.** 내려받은 채 바탕화면에 있었다. 옮기고 600 을 준 뒤
`~/.ssh/config` 에 `Host staysync` 를 적었다(4절). 서버 초기 상태는 Ubuntu 24.04,
커널 6.17, 메모리 1,907MB, 디스크 58GB(2.6GB 사용), 시간대 UTC, Docker 없음.

```bash
ssh -i ~/.ssh/LightsailDefaultKey-ap-northeast-2.pem ubuntu@3.35.108.26
```

```bash
# 스왑 2GB. 컨테이너 셋이 1.2~1.5GB 를 쓰므로 스파이크를 받아 줄 자리가 있어야 한다
sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile
sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
sudo sysctl vm.swappiness=10 && echo 'vm.swappiness=10' | sudo tee -a /etc/sysctl.conf

# Docker 공식 저장소에서 설치한다 (Ubuntu 의 docker.io 패키지는 compose v2 가 없다)
sudo apt-get update && sudo apt-get install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] \
  https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo $VERSION_CODENAME) stable" \
  | sudo tee /etc/apt/sources.list.d/docker.list
sudo apt-get update && sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
sudo usermod -aG docker ubuntu   # 다시 로그인해야 적용된다

# 배포 디렉터리
sudo mkdir -p /opt/staysync && sudo chown ubuntu:ubuntu /opt/staysync

# 시간대. 백업 cron 과 로그 시각이 KST 로 찍히게
sudo timedatectl set-timezone Asia/Seoul
```

결과 — 스왑 2,047MB(사용 0), Asia/Seoul, Docker 29.8.0, Compose v5.5.1.
`apt` 가 needrestart 로 서비스 재시작 목록을 길게 찍는데 무시해도 된다.

### `.env`

`deploy/.env.example` 을 참고해 `/opt/staysync/.env` 를 만든다. **저장소에 넣지 않고
권한은 600 이다.**

```bash
cd /opt/staysync
cat > .env <<EOF
SITE_ADDRESS=staysync.kr
PUBLIC_BASE_URL=https://staysync.kr
POSTGRES_USER=staysync
POSTGRES_PASSWORD=$(openssl rand -base64 24 | tr -d '/+=')
POSTGRES_DB=staysync
JWT_SECRET=$(openssl rand -base64 48)
GUEST_DATA_KEY=$(openssl rand -base64 32)
PORTONE_STORE_ID=
PORTONE_CHANNEL_KEY=
PORTONE_API_SECRET=
PORTONE_WEBHOOK_SECRET=
EOF
chmod 600 .env
```

- `JWT_SECRET`·`GUEST_DATA_KEY` 는 **처음 한 번 만들고 바꾸지 않는다.** 바꾸면 전자는
  모두 로그아웃, 후자는 기존 게스트 연락처를 못 읽는다
- `application-local.yml` 의 고정값을 절대 여기 넣지 않는다
- 포트원 넷은 결제 확인(9절)을 할 때 채운다. 비어 있어도 기동은 되고 결제만 막힌다
- Windows Git Bash 에서 `openssl rand` 로 만들면 끝에 `\r` 이 붙어 Base64 디코딩이
  깨진다(로컬 스모크 테스트에서 실제로 걸렸다). **키는 서버에서 만든다** — 위 heredoc
  을 `ssh staysync '...'` 의 작은따옴표 안에 통째로 넣어 서버 셸이 전개하게 했다
- 값을 찍지 않고 확인하는 법: `awk -F= '{ printf "%-24s len=%d cr=%d\n", $1, length($2), gsub(/\r/,"",$2) }' .env`.
  실제 결과 — `JWT_SECRET len=64`, `GUEST_DATA_KEY len=43`(끝의 `=` 는 `-F=` 가
  잘라 44 가 43 으로 보인다), `POSTGRES_PASSWORD len=31`, 전부 `cr=0`

## 4. 첫 배포 `[확인]` 2026-09-14

**`deploy/push.sh staysync` 한 번으로 셋이 떴고 app 이 healthy 로 끝났다**(완료 조건 3).
이미지 내려받기 포함 5분 안쪽. 실제로 본 값:

| | |
|---|---|
| `compose ps` | `app (healthy)` · `postgres (healthy)` · `caddy`. postgres 의 PORTS 는 `5432/tcp`(호스트 매핑 없음), caddy 만 `0.0.0.0:80·443` |
| `curl -sI https://staysync.kr/` | `HTTP/1.1 200 OK`, `Alt-Svc: h3` |
| `curl -sI http://staysync.kr/` | `308 Permanent Redirect` → https |
| 인증서 | Let's Encrypt (`CN=YE2`), 2026-09-14 ~ 12-13. Caddy 가 알아서 갱신한다 |
| `POST /api/auth/login {}` | `400 VALIDATION_FAILED` — Caddy 를 지나 앱까지 닿는다 |
| Flyway | V1~V7 **7줄 전부 `success = t`**, `2 pgvector` 포함 |
| pgvector | `vector 0.8.6`, `knowledge_chunk.embedding` = `vector(1536)`, `idx_chunk_vector hnsw` 있음 |
| 세션 | 아래 |
| 이미지 | `staysync-app 458MB`, `pgvector/pgvector:pg16 621MB`, `caddy:2-alpine 89MB` |

**세션 확인(완료 조건 4)은 일회용 계정으로 했고 끝나고 지웠다.** 7절이 아직이라
심사자 계정이 없다. `smoke-*@staysync.kr` 둘을 만들어 — Git Bash 의 curl 은 한글
본문을 cp949 로 깨뜨려 400 을 내므로(확인-08 5절) 파이썬으로 — 다음을 봤다.

- `Set-Cookie: refresh_token=…; Path=/api/auth; Max-Age=1209600; Secure; HttpOnly; SameSite=Strict`
- 쿠키만으로 `POST /api/auth/refresh` 200, **회전된 쿠키로 한 번 더 200**, 새 액세스
  토큰으로 `GET /api/properties` 200
- 브라우저: 로그인 → 캘린더 빈 상태 → 주소창으로 `/channels` 전체 로드 → 로그인
  유지, 채널 화면 렌더(Caddy 의 `try_files` SPA 폴백도 이걸로 확인). 콘솔 에러는
  로그인 전 복구 시도의 401 하나뿐 — 확인-08 과 같다

지운 뒤 `user_account`·`organization`·`refresh_token`·`audit_log` 전부 0 행이다.
`audit_log.actor_id` 는 FK 가 아니라 `user_account` 를 먼저 지워도 막히지 않는다.

개발 PC 에서:

```bash
deploy/push.sh ubuntu@3.35.108.26
```

하는 일 — `./gradlew :bootJar`, `npm run build`, jar·번들·compose·Caddyfile 을
`/opt/staysync` 로 scp, `docker compose build app && up -d`, app 이 healthy 가 될
때까지 대기. **첫 실행은 이미지 내려받기(JRE·pgvector·caddy ≈ 500MB)로 2~3분 걸린다.**

`ssh` 가 키를 못 찾으면 `~/.ssh/config` 에 적어 둔다:

```
Host staysync
  HostName 3.35.108.26
  User ubuntu
  IdentityFile ~/.ssh/LightsailDefaultKey-ap-northeast-2.pem
```

그러면 `deploy/push.sh staysync` 다.

## 5. 열린 포트 확인 `[확인]` 2026-09-14 (완료 조건 6)

개발 PC 에서 `Test-NetConnection 3.35.108.26 -Port N` — **5432 False · 6379 False ·
8080 False · 443 True · 22 True.** 서버 안 `ss -tlnp` 는 `docker-proxy` 의 80·443
넷(IPv4·IPv6)뿐이다. 5432 는 compose 내부 네트워크에서만 열려 있다.

**밖에서** (개발 PC):

```bash
nc -zv -w 3 3.35.108.26 5432   # Connection timed out 이어야 한다
nc -zv -w 3 3.35.108.26 6379   # 같다 (Redis 는 없지만 열려 있지 않다는 것을 남긴다)
nc -zv -w 3 3.35.108.26 443    # succeeded
```

Windows 라면 `Test-NetConnection 3.35.108.26 -Port 5432` 로 `TcpTestSucceeded : False`.

**서버 안에서** 호스트가 무엇을 듣는지:

```bash
ssh staysync 'sudo ss -tlnp | grep -E ":(80|443|5432|6379|8080) "'
```

80·443 만 `docker-proxy` 가 듣고 5432·8080 은 없어야 한다. compose 가 `ports` 를
caddy 에만 뒀기 때문이다.

## 6. 백업과 복원 `[확인]` 2026-09-14 (완료 조건 7·8)

**재기동 후 데이터** (7): 계정이 없어 표식 테이블로 봤다 — `deploy_smoke` 에 행 하나
넣고 `docker compose restart`, app 이 healthy 로 돌아온 뒤 그 행이 그대로 있었다(표는
지웠다). 볼륨은 `staysync_pgdata`·`staysync_caddy_data` 둘. `docker compose down` 은
볼륨을 지우지 않는다 — **`down -v` 만 지운다. 절대 치지 않는다.**

**복원 결과** (8): `pg_dump -Fc` 98KB(빈 스키마). `restore_test` 에 복원해 운영과 같은
질의로 대조 — **flyway 7행 · 테이블 28개 · `embedding` 타입 `vector`**, 양쪽 동일.
`restore_test` 는 지웠다. cron 은 `crontab -l` 에 한 줄이 있고 `cron` 서비스가 active 다.

**`pg_dump` cron** (8):

```bash
mkdir -p /opt/staysync/backup
cat > /opt/staysync/backup.sh <<'EOF'
#!/usr/bin/env bash
set -euo pipefail
cd /opt/staysync
docker compose exec -T postgres pg_dump -U staysync -d staysync -Fc \
  > backup/staysync-$(date +%F).dump
find backup -name 'staysync-*.dump' -mtime +14 -delete
EOF
chmod +x /opt/staysync/backup.sh
# 빈 crontab 에 첫 줄을 넣을 때는 이 형태다. `(crontab -l | grep -v …; echo …)` 는
# crontab 이 비어 있으면 grep 이 1 을 돌려줘 set -e 아래에서 조용히 죽는다 — 실제로 그랬다
printf '30 4 * * * /opt/staysync/backup.sh >> /opt/staysync/backup/backup.log 2>&1\n' | crontab -
crontab -l
```

새벽 4:30(KST 기준이면 서버 시간대를 먼저 `timedatectl set-timezone Asia/Seoul`),
14일 보관. 스냅샷(2절 4번)이 디스크 전체를 받쳐 주므로 dump 는 논리 백업 한 겹이다.

**복원해 본다.** 해 보지 않은 백업은 백업이 아니다. **운영 DB 에 하지 않고 옆에 빈
DB 를 만들어 거기에 넣는다:**

```bash
cd /opt/staysync
./backup.sh
docker compose exec postgres createdb -U staysync restore_test
docker compose exec -T postgres pg_restore -U staysync -d restore_test < backup/staysync-$(date +%F).dump
docker compose exec postgres psql -U staysync -d restore_test \
  -c 'select count(*) from reservation' -c 'select count(*) from flyway_schema_history'
docker compose exec postgres dropdb -U staysync restore_test
```

건수가 운영과 같으면 된다. 7절 뒤에는 `reservation` 건수가 진짜 대조값이 된다. 실제 복원이 필요할 때는 `down` → `up -d postgres` →
`dropdb`/`createdb staysync` → 위 `pg_restore` → `up -d`.
