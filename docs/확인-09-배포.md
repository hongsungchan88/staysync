# 확인 09. 배포 절차서 — 1차 심사용

- 작성일: 2026-09-12
- 범위: 작업지시-15 의 C·D·F(서버 작업). 저장소 안의 B 는 `deploy/` 에 있다
- 관련: 작업지시-15, 확인-07(포트원 웹훅), 조사-02(iCal)

**다음 사람이 그대로 따라 할 수 있는 것**이 이 문서의 목적이다. 손으로 하되 재현
가능해야 한다(작업지시-15 5절 3번).

**상태 표시.** 각 절 머리의 `[확인]` 은 실제로 해 보고 적은 것, `[미실행]` 은 절차만
적은 것이다. 이 문서를 처음 쓴 시점에는 서버가 없었다 — AWS 계정·도메인은 사람이
만들어야 하고, 개발 PC 에는 Docker 가 없어 compose 를 로컬에서 돌릴 수 없었다.
**`[미실행]` 절은 서버 작업을 하면서 `[확인]` 으로 바꾸고 실측값을 채운다.**

## 1. 구성

| | |
|---|---|
| 서버 | AWS Lightsail, **Linux/Unix · Ubuntu 24.04 LTS · 2GB RAM / 2 vCPU / 60GB SSD**, 서울(ap-northeast-2) |
| 컨테이너 | app(JRE 21 + jar) · postgres(`pgvector/pgvector:pg16`) · caddy. **셋이다** — Redis 는 없다(아래) |
| 프록시·HTTPS | Caddy. Let's Encrypt 자동 발급·갱신 |
| 시크릿 | 서버의 `/opt/staysync/.env`, 권한 600 |
| 배포 | 개발 PC 에서 `deploy/push.sh user@host` |

**Redis 가 없는 이유.** 작업지시-15 는 넷을 적었지만 코드에 Redis 를 읽는 곳이 없다.
`UnitLock` 구현은 `LocalUnitLock` 하나이고 `build.gradle` 의 redis 의존성은 주석이다.
`staysync.lock.type` 도 아무도 읽지 않는다. 붙는 것이 없는 컨테이너를 2GB 에 올리지
않았다. 앱이 한 컨테이너뿐이라 JVM 락으로 충분하고, 인스턴스를 늘리는 순간 Redis 락
구현부터 필요하다.

**이미지를 서버에서 만드는 것처럼 보이지만 빌드는 개발 PC 다.** `deploy/app/Dockerfile`
은 `COPY staysync.jar` 뿐이다. `bootJar` 와 `npm run build` 는 push.sh 가 개발 PC 에서
돌리고, 서버의 `docker build` 는 레이어 하나를 더하는 일이라 메모리를 거의 쓰지 않는다.
2GB 에서 bootJar 를 돌리지 않는다는 4절의 제약을 이렇게 지킨다.

## 2. 서버 만들기 `[미실행]`

Lightsail 콘솔에서:

1. **인스턴스 생성** — 리전 서울(ap-northeast-2), 플랫폼 Linux/Unix, 블루프린트 OS
   전용 **Ubuntu 24.04 LTS**, 플랜 **$12 (2GB RAM, 2 vCPU, 60GB SSD, 3TB 전송)**.
   SSH 키는 기본 키를 내려받아 `~/.ssh/` 에 둔다(권한 600)
2. **고정 IP** — 네트워킹 탭에서 고정 IP 를 만들어 인스턴스에 붙인다. 붙어 있는 동안
   무료다. **인스턴스를 지울 때 고정 IP 도 함께 지운다** — 떠 있는 고정 IP 는 요금이 붙는다
3. **방화벽** — 네트워킹 탭의 IPv4 방화벽을 **SSH 22, HTTP 80, HTTPS 443** 셋만 둔다.
   기본으로 22·80 이 열려 있으니 443 을 더한다. **5432·6379 는 만들지 않는다**
4. **자동 스냅샷** — 스냅샷 탭에서 자동 스냅샷을 켠다. 하루 한 번, 7일 보관.
   스냅샷 저장은 GB·월당 $0.05 이고 증분이라 실제로는 몇 GB 다
5. **DNS** — 도메인의 A 레코드를 고정 IP 로 향하게 한다. 도메인이 Lightsail 밖에
   있으면 그쪽 등록기관에서 한다. `dig +short <도메인>` 이 고정 IP 를 돌려줄 때까지
   기다린 뒤 4절로 간다 — Caddy 가 인증서를 받으려면 DNS 가 먼저 맞아야 한다

## 3. 서버 준비 `[미실행]`

```bash
ssh -i ~/.ssh/LightsailDefaultKey-ap-northeast-2.pem ubuntu@<고정IP>
```

```bash
# 스왑 2GB. 컨테이너 셋이 1.2~1.5GB 를 쓰므로 스파이크를 받아 줄 자리가 있어야 한다
sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile
sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
sudo sysctl vm.swappiness=10 && echo 'vm.swappiness=10' | sudo tee -a /etc/sysctl.conf

# Docker 공식 저장소에서 설치한다 (Ubuntu 의 docker.io 패키지는 compose v2 가 없다)
sudo apt-get update && sudo apt-get install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] \
  https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo $VERSION_CODENAME) stable" \
  | sudo tee /etc/apt/sources.list.d/docker.list
sudo apt-get update && sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
sudo usermod -aG docker ubuntu   # 다시 로그인해야 적용된다

# 배포 디렉터리
sudo mkdir -p /opt/staysync && sudo chown ubuntu:ubuntu /opt/staysync
```

### `.env`

`deploy/.env.example` 을 참고해 `/opt/staysync/.env` 를 만든다. **저장소에 넣지 않고
권한은 600 이다.**

```bash
cd /opt/staysync
cat > .env <<EOF
SITE_ADDRESS=<도메인>
PUBLIC_BASE_URL=https://<도메인>
POSTGRES_USER=staysync
POSTGRES_PASSWORD=$(openssl rand -base64 24 | tr -d '/+=')
POSTGRES_DB=staysync
JWT_SECRET=$(openssl rand -base64 48)
GUEST_DATA_KEY=$(openssl rand -base64 32)
PORTONE_STORE_ID=
PORTONE_CHANNEL_KEY=
PORTONE_API_SECRET=
PORTONE_WEBHOOK_SECRET=
EOF
chmod 600 .env
```

- `JWT_SECRET`·`GUEST_DATA_KEY` 는 **처음 한 번 만들고 바꾸지 않는다.** 바꾸면 전자는
  모두 로그아웃, 후자는 기존 게스트 연락처를 못 읽는다
- `application-local.yml` 의 고정값을 절대 여기 넣지 않는다
- 포트원 넷은 결제 확인(9절)을 할 때 채운다. 비어 있어도 기동은 되고 결제만 막힌다
- Windows Git Bash 에서 `openssl rand` 로 만들면 끝에 `\r` 이 붙어 Base64 디코딩이
  깨진다(로컬 스모크 테스트에서 실제로 걸렸다). **키는 서버에서 만든다**

## 4. 첫 배포 `[미실행]`

개발 PC 에서:

```bash
deploy/push.sh ubuntu@<고정IP>
```

하는 일 — `./gradlew :bootJar`, `npm run build`, jar·번들·compose·Caddyfile 을
`/opt/staysync` 로 scp, `docker compose build app && up -d`, app 이 healthy 가 될
때까지 대기. **첫 실행은 이미지 내려받기(JRE·pgvector·caddy ≈ 500MB)로 2~3분 걸린다.**

`ssh` 가 키를 못 찾으면 `~/.ssh/config` 에 적어 둔다:

```
Host staysync
  HostName <고정IP>
  User ubuntu
  IdentityFile ~/.ssh/LightsailDefaultKey-ap-northeast-2.pem
```

그러면 `deploy/push.sh staysync` 다.

### 뜬 것을 확인한다 (완료 조건 3·4·5)

```bash
ssh staysync 'cd /opt/staysync && docker compose ps'     # 셋 다 Up, app·postgres (healthy)
curl -sI https://<도메인>/ | head -1                        # HTTP/2 200
curl -s https://<도메인>/api/auth/login -X POST -H 'Content-Type: application/json' -d '{}' | head -c 200
                                                            # 400 이면 앱까지 닿은 것이다
```

**Flyway 와 pgvector** (완료 조건 5):

```bash
ssh staysync 'cd /opt/staysync && docker compose exec postgres \
  psql -U staysync -d staysync -c "select version, description, success from flyway_schema_history order by installed_rank"'
```

V1 부터 V7 까지 **일곱 줄이 전부 `success = t`** 여야 한다. local 프로파일과 달리 V2 가
끼어 있다.

```bash
ssh staysync 'cd /opt/staysync && docker compose exec postgres \
  psql -U staysync -d staysync -c "select extname, extversion from pg_extension where extname = '"'"'vector'"'"'" \
  -c "\d knowledge_chunk"'
```

`vector` 확장 행이 있고 `embedding` 컬럼 타입이 `vector(1536)` 이면 V2 가 실제로
적용된 것이다.

**세션** (완료 조건 4): 브라우저로 `https://<도메인>` 을 열어 로그인하고 새로고침한다.
로그인 상태가 유지되면 `Secure` 쿠키가 저장되고 갱신이 도는 것이다. 개발자 도구 →
Application → Cookies 에 `refresh_token` 이 `Secure`·`HttpOnly`·`SameSite=Strict` 로
있어야 한다. (계정은 7절에서 만든다)

## 5. 열린 포트 확인 `[미실행]` (완료 조건 6)

**밖에서** (개발 PC):

```bash
nc -zv -w 3 <고정IP> 5432   # Connection timed out 이어야 한다
nc -zv -w 3 <고정IP> 6379   # 같다 (Redis 는 없지만 열려 있지 않다는 것을 남긴다)
nc -zv -w 3 <고정IP> 443    # succeeded
```

Windows 라면 `Test-NetConnection <고정IP> -Port 5432` 로 `TcpTestSucceeded : False`.

**서버 안에서** 호스트가 무엇을 듣는지:

```bash
ssh staysync 'sudo ss -tlnp | grep -E ":(80|443|5432|6379|8080) "'
```

80·443 만 `docker-proxy` 가 듣고 5432·8080 은 없어야 한다. compose 가 `ports` 를
caddy 에만 뒀기 때문이다.

## 6. 백업과 복원 `[미실행]` (완료 조건 7·8)

**재기동 후 데이터** (7): `docker compose restart` 뒤 로그인이 되고 캘린더가 그대로면
`pgdata` 볼륨이 붙은 것이다. `docker compose down` 은 볼륨을 지우지 않는다 —
**`down -v` 만 지운다. 절대 치지 않는다.**

**`pg_dump` cron** (8):

```bash
mkdir -p /opt/staysync/backup
cat > /opt/staysync/backup.sh <<'EOF'
#!/usr/bin/env bash
set -euo pipefail
cd /opt/staysync
docker compose exec -T postgres pg_dump -U staysync -d staysync -Fc \
  > backup/staysync-$(date +%F).dump
find backup -name 'staysync-*.dump' -mtime +14 -delete
EOF
chmod +x /opt/staysync/backup.sh
(crontab -l 2>/dev/null; echo '30 4 * * * /opt/staysync/backup.sh >> /opt/staysync/backup/backup.log 2>&1') | crontab -
```

새벽 4:30(KST 기준이면 서버 시간대를 먼저 `timedatectl set-timezone Asia/Seoul`),
14일 보관. 스냅샷(2절 4번)이 디스크 전체를 받쳐 주므로 dump 는 논리 백업 한 겹이다.

**복원해 본다.** 해 보지 않은 백업은 백업이 아니다. **운영 DB 에 하지 않고 옆에 빈
DB 를 만들어 거기에 넣는다:**

```bash
cd /opt/staysync
./backup.sh
docker compose exec postgres createdb -U staysync restore_test
docker compose exec -T postgres pg_restore -U staysync -d restore_test < backup/staysync-$(date +%F).dump
docker compose exec postgres psql -U staysync -d restore_test \
  -c 'select count(*) from reservation' -c 'select count(*) from flyway_schema_history'
docker compose exec postgres dropdb -U staysync restore_test
```

건수가 운영과 같으면 된다. 실제 복원이 필요할 때는 `down` → `up -d postgres` →
`dropdb`/`createdb staysync` → 위 `pg_restore` → `up -d`.

## 7. 초기 데이터 `[미실행]` (완료 조건 10)

빈 데이터베이스에서 시작한다. `tools/seed_demo.py` 를 **쓰지 않는다.**

### 심사자 계정

회원가입 화면이 없다. API 로 만든다. 심사자마다 조직이 다르므로 계정마다 `orgName`
을 준다 — 조직 스코핑이 역할별 인가를 대신하는 방식이다(작업지시-15 3절).

```bash
curl -s https://<도메인>/api/auth/signup -H 'Content-Type: application/json' -d '{
  "email": "<심사자 이메일>", "password": "<임시 비밀번호>",
  "displayName": "<이름>", "orgName": "<조직 이름>"
}'
```

응답의 `accessToken` 으로 아래를 이어서 한다. 비밀번호는 심사자에게 따로 전한다
(비밀번호 변경 화면도 없다 — 처음부터 그 사람이 쓸 값을 받아 넣는 편이 낫다).

### 숙소·판매 단위·요금

```bash
T=<accessToken>
curl -s https://<도메인>/api/properties -H "Authorization: Bearer $T" -H 'Content-Type: application/json' \
  -d '{"name": "<숙소 이름>", "address": "<주소>"}'                      # → id
curl -s https://<도메인>/api/properties/<id>/units -H "Authorization: Bearer $T" -H 'Content-Type: application/json' \
  -d '{"name": "<판매 단위>", "unitKind": "ENTIRE_PLACE", "totalUnits": 1, "basePrice": 180000}'
```

`unitKind` 는 `ENTIRE_PLACE` / `PRIVATE_ROOM` / `SHARED_ROOM`. 요금은 화면에서 넣는다 —
캘린더에서 기간을 끌어 일괄 편집(고정값). **판매 단위마다 따로** 넣는다. 한 번에
묶으면 전부 같은 값이 된다(확인-08).

### iCal 연결 하나 (완료 조건 11)

화면에서 한다: 채널 연결 → 에어비앤비(iCal) → 업체가 준 주소를 넣고 판매 단위 하나에
매핑. **어느 주소가 어느 판매 단위인지 업체에 확인한 뒤** 넣는다. 첫 폴링은 15분 안에
돈다. 급하면 앱을 재기동한다(기동 직후 한 번 돈다).

- iCal 주소는 **이 문서에도, 커밋에도, 대화에도 적지 않는다.** 주소를 아는 사람은
  그 숙소의 예약 일정을 전부 읽는다
- **우리가 발행하는 iCal 주소를 업체 리스팅에 등록하지 않는다.** 등록하는 순간 영업
  중인 리스팅의 날짜를 우리가 막고 푼다. 수신만 한다
- 파서가 실제 피드에서 만난 것은 조사-02 에 문단으로 더한다

## 8. 다시 배포하기

코드가 바뀌면 개발 PC 에서 `deploy/push.sh staysync` 를 다시 친다. 그게 전부다.
push.sh 는 jar·번들을 새로 만들어 올리고 `up -d` 로 바뀐 app 컨테이너만 다시 만든다.
postgres·caddy 는 그대로이고 데이터·인증서도 그대로다. **중단 시간은 app 이 다시
뜨는 20~40초다.** 무중단은 범위 밖이다(작업지시-15 3절).

마이그레이션이 더해졌으면 app 이 뜨면서 Flyway 가 적용한다. 4절의 psql 로 확인한다.

굴러가는 것을 볼 때:

```bash
ssh staysync 'cd /opt/staysync && docker compose logs -f --tail=100 app'
ssh staysync 'docker stats --no-stream'          # 컨테이너별 메모리 — 10절에 적는다
```

## 9. 포트원 웹훅 `[미실행]` (완료 조건 13)

확인-07 의 절차에서 터널만 빠진다. 포트원 콘솔 → 결제알림(Webhook) 에 등록할 주소:

```
https://<도메인>/public/payments/portone/webhook
```

그 뒤는 확인-07 그대로 — 위젯에서 예약·테스트 결제, 웹훅 수신, 리포트 반영.
**이것이 P4 완료 조건 15·16 의 판정이다.** 판정하면 `p4-complete` 태그를 단다.

## 10. 실측 `[미실행]`

서버 작업을 하면서 채운다. 작업지시-15 7절이 반드시 남기라고 한 것들이다.

### 메모리

| 컨테이너 | 유휴 | 캘린더·리포트 조작 중 | 비고 |
|---|---|---|---|
| app | | | `-Xmx640m`. 로컬 스모크(Windows, 유휴)에서는 RSS 473MB 였다 |
| postgres | | | |
| caddy | | | |
| 합계 / 스왑 사용 | | | `free -m` |

**2GB 로 2차까지 가는지의 판단 근거.** 합계가 1.5GB 를 넘거나 스왑을 꾸준히 쓰면
4GB($24)로 올린다 — 스냅샷 뒤 리사이즈 한 번이다. 수강생 수십 명이 동시에 캘린더를
열어도 앱 힙이 늘 뿐 컨테이너 수는 같으므로, 기준은 `docker stats` 의 app 메모리가
힙 상한 근처에서 GC 로 버티는지다.

### iCal 파서

조사-02 에 더한다. 미게시 피드와 무엇이 달랐는지가 본체다.
